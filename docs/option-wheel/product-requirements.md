# 期权车轮策略模块：产品需求

状态：Draft 0.1
更新时间：2026-08-29

## 1. 产品定位

本模块是家庭工作台投资板块中的期权卖方决策助手。它围绕家庭成员日常使用的
“观察市场—比较方案—人工决策—记录真实成交—管理持仓—复盘结果”设计，弥补仅凭感觉选择
行权价、到期日、权利金和 Roll 方案时的计算与证据缺口。

模块不承诺预测市场，也不以“最大化权利金”单一目标驱动交易。产品必须同时展示收益、到期价内
风险、资金占用、尾部损失、流动性、技术状态和事件风险，并允许稳定地给出“暂不操作”。

## 2. 用户目标与非目标

### 2.1 用户目标

1. 每周比较 TSLA 等标的最近周五及其他合理 DTE 的 Cash-Secured Put。
2. 在尽量避免被指派的前提下，提高可实现的净权利金收入。
3. Put 被指派后，为同一账户内的实际股票比较 Covered Call。
4. 对已持有的空头 Put/Call 比较持有、平仓、Roll、接受指派等方案。
5. 在财报、重大事件或市场显著动荡时识别风险，并能够暂停策略。
6. 保存当时使用的行情、概率、技术指标、事件证据、AI 解释和人工选择，供后续复盘。

### 2.2 非目标

- 不自动下单、改单或撤单。
- 不把 AI 输出当作交易事实、实时价格或保证结果。
- 不使用融资、裸卖 Call、组合保证金或跨账户担保。
- 不以权利金金额、年化收益率或胜率单项指标替代完整风险判断。
- 第一版不处理交割物不明确的调整合约、指数期权、价差组合或多腿套利。

## 3. 已确认策略档案

| 项目 | 规则 |
| --- | --- |
| 参与账户 | 致富证券（公户）、盈透证券 |
| 权限 | 家庭共享；`viewer` 只读，`member` 可保存不放宽安全约束的偏好与人工选择，硬约束仅 `admin` 维护 |
| Put 默认期限 | 周一比较最近周五到期合约；同时比较其他合理 DTE |
| 权利金偏好 | 每张 200–400 美元；可低于或高于，不作为硬门槛 |
| Put 目标 | 收取权利金为主，尽量避免指派 |
| 财报 | 默认不跨财报；单次解除必须明确确认并留痕 |
| Delta | 不设置固定默认值，仅作为风险辅助指标 |
| Covered Call | 默认行权价不低于该批股票指派买入价 |
| 单标的上限 | 潜在指派金额不超过该账户最新可用总资产 |
| 担保方式 | 全额现金担保，不使用融资或组合保证金 |
| 市场动荡 | 支持全局、账户、标的暂停；恢复需人工确认 |

账户总额约 12 万美元只作为当前背景，不写死为配置。系统应读取对应账户最新、完整且可审计的
资产与现金状态；数据缺失时不推断。

### 3.1 账户事实前置条件

致富证券（公户）和盈透证券当前直接映射到 `/portfolio/` 中由用户手工维护的对应投资账户，不连接
真实券商 API，也不能把 Futu OpenD 的行情登录身份当作任一投资账户。每份快照至少保存来源账户、
币种、已结算现金、待结算资金、总资产净值、融资/借贷人工确认、实际持仓、未平仓义务和 `as_of`。
以后接入券商只读接口时，只替换账户事实适配器，不改变车轮风险规则。

任一必需字段缺失、过期、无法映射到账户，或快照显示正在使用融资/借贷时，该账户的新 Sell Put
统一为 `unknown/ineligible`。Futu 在本模块只作为市场数据源，除非以后另行验证并批准账户适配器。

## 4. 核心使用流程

### 4.1 周一选择 Sell Put

1. 首页列出当前市场状态、暂停状态、参与账户可用现金及已有担保占用。
2. 用户进入标的页，查看正股行情、技术状态、最近七天证据和未来已知事件。
3. 系统比较最近周五、两至三周及较长期的合格 Put，而不是只搜索 200–400 美元权利金。
4. 页面分别给出“低价内风险”“收益风险平衡”“提高权利金”和“暂不操作”方案。
5. 用户保存选择或忽略；保存选择仍不是成交。
6. 用户在券商成交后，使用既有交易流程录入或导入真实交易，再显式关联车轮周期。

### 4.2 管理未平仓 Put

每天对真实未平仓 Put 展示：

- 剩余 DTE、当前 Bid/Ask、未实现损益、价内外程度和剩余时间价值；
- 到期价内概率、期间触及行权价风险和技术/事件变化；
- 继续持有、买回平仓、原行权价 Roll Out、降低行权价 Roll Down and Out、接受指派；
- 每个 Roll 的旧仓平仓支出、新仓收入、净 Credit/Debit、新增占用天数、新盈亏平衡点和新概率；
- 累计净权利金，不把新开合约的毛收入误称为 Roll 利润。

### 4.3 Put 指派与 Covered Call

1. 状态只能依据券商实际指派与已记录交易变化，不能根据收盘价自动推断。
2. 现金担保转换为同一账户内的实际股票数量。
3. Covered Call 只能使用未被其他 Call 占用的股票。
4. 每张 Call 必须引用具体指派/买入股票批次；混合批次时拆成多个腿，或按所覆盖批次中最高的每股
   买入价作为行权价下限，不得用低成本批次覆盖高成本批次。
5. 默认行权价不低于对应批次的指派买入价；没有合理权利金时比较延长 DTE 或等待。
6. 提前指派和部分指派必须保留实际日期、数量和交易关联；分配数量不得超过实际成交或指派数量。

### 4.4 暂停与恢复

- 用户可创建全局、账户或标的级暂停，并填写原因和复核日期。
- 代码规则判定为“建议暂停”时形成规则硬暂停，新卖 Put/Call 不得显示为可执行；仍可展示持仓管理方案。
- 全局、账户和标的暂停任一生效即门控；展示与解释优先级为“全局 > 账户 > 标的”，不以较窄粒度覆盖
  较宽粒度暂停。
- 人工暂停只能由创建者或管理员显式解除；规则暂停达到解除条件后仍需管理员确认恢复并留痕。
- 暂停时仍展示持仓风险和需要处理的已开仓合约，但不生成新的卖出建议。
- 恢复操作保存操作者、时间和理由。

## 5. 页面结构

### 5.1 车轮首页

优先展示：

1. 今天必须处理：临近到期、价内风险上升、财报/除息、数据异常。
2. 当前暂停和市场状态。
3. 参与账户的现金担保与股票覆盖摘要。
4. 当日可比较的标的与“暂不操作”结论。
5. 最近周期结果和概率校准摘要。

行情源权限、订阅额度和运行日志放在次级“数据状态”页面，不作为日常首页主角。

### 5.2 标的详情

- 正股行情和数据时间；
- 趋势、动量、波动率、ATR、成交量和支撑/压力；
- 最近七天新闻证据与未来七天已知事件；
- 按到期日分组的期权链；
- 候选合约多目标比较；
- 历史车轮周期和相似情形结果。

### 5.3 持仓管理

按账户和标的展示真实未平仓期权、担保/覆盖占用、累计权利金、Roll 方案和人工处理入口。

### 5.4 决策详情

冻结展示行情、技术、事件、规则版本、候选列表、AI 版本、人工选择和之后的真实结果。历史页面不得
使用当前行情重写当时结论。

## 6. 候选选择与指标体系

### 6.1 硬性禁入条件

任一条件不满足时，不得显示为可执行候选：

- 人工暂停仍有效；
- 规则市场状态为“建议暂停”或任一更高层级规则暂停仍有效；
- 报价缺失、延迟、过期、Bid/Ask 异常或流动性不满足策略；
- 到期前跨越已知财报，且没有单次明确解除；
- Put 全额担保现金不足或状态未知；
- Call 覆盖股票不足、跨账户或已被其他合约占用；
- 单标的潜在指派金额超过账户总资产；
- 合约交割物、乘数、行权方式或公司行动状态不明确；
- 关键 FX、费用、账户或事件数据缺失；
- 券商容量快照过期、账户身份无法映射，或融资/借贷状态不是明确的“未使用”。

候选本身不是订单，也不锁定现金或股票。资格计算必须原子汇总同一账户现有全部真实未平仓义务和
资源占用；同一决策页的多个候选默认互斥。用户组合选择多个候选时，系统按组合重新计算总担保和
单标的名义金额。保存选择只保存有有效期的意向，不形成资源预留；录入真实成交时再次校验并建立硬
占用。因此，来自不同运行批次的两个“合格候选”不得被解释为可以同时执行。

### 6.2 三个主要决策指标

指标保持独立，不压缩成单一神秘分数：

1. **净权利金效率**：扣除买回成本、费用和税费后的净权利金，除以全额担保资金和实际占用天数。
2. **到期价内风险**：以 Futu 概率为主要市场隐含值，结合 Delta 和历史类似情形校验。
3. **指派后尾部风险**：行权价相对支撑、ATR、压力价格和账户集中度的风险。

辅助指标包括：Bid/Ask 价差、盘口量、成交量、OI、IV、HV、IV Rank/Percentile、Theta、行权价距离、
有效买入价、盈亏平衡点、区间收益和年化收益。

### 6.3 候选展示

- **低价内风险**：优先降低到期价内概率，允许权利金低于偏好区间。
- **收益风险平衡**：在风险可接受时优先接近每张 200–400 美元。
- **提高权利金**：明确显示相对平衡方案增加了多少风险和资金占用。
- **暂不操作**：说明触发的暂停、事件、价格或数据原因。

候选采用 Pareto 前沿或分层规则比较，不用可被高权利金轻易“刷高”的单一综合分。

## 7. 概率口径

页面同时展示但不得混淆：

- **Futu 到期价内/行权概率**：保存来源、模型时点和原始字段名；不称为保证指派概率。
- **期间触及行权价概率**：用于衡量中途浮亏和 Roll 压力，通常高于到期价内概率。
- **历史类似情形到期价内率**：按 DTE、行权价距离、ATR、波动率和市场状态分组，无足够样本时不展示。
- **绝对 Delta**：风险辅助指标，不直接命名为指派概率。

系统保存每次预测和最终真实结果，按概率区间检查校准度。新上市的 SKHY、SPCX 等历史不足时显示
样本数和低置信度，不用缺失值冒充中性结果。

## 8. 市场状态与事件政策

市场状态分为“平静、正常、警戒、建议暂停”，由代码计算可解释信号：

- 大盘与成长股波动、趋势和跳空；
- 标的 ATR、已实现波动、短期跌幅、成交量和 IV 变化；
- 财报、除息、宏观日程和有证据支持的重大事件；
- 数据完整性和来源冲突。

AI 只提取事件特征和解释影响，最终门控由代码和用户策略决定。来源不足或冲突不解释为“没有风险”。
“建议暂停”的进入阈值、解除阈值和最短观察期必须版本化；规则不能自动解除人工暂停，规则暂停解除也
需要管理员确认。财报、除息或其他关键事件数据不可用时，页面只能显示“数据不可用”，不能生成可执行
的新卖出候选。

## 9. AI 输出要求

AI 只能在代码已生成的合格候选中引用候选 ID，并输出：

- 偏好候选或暂不操作；
- 周度与其他 DTE 的取舍；
- 技术面、波动率和事件证据；
- 主要风险、未知项和结论失效条件；
- 证据引用 ID。

服务端拒绝不存在的合约、候选或证据引用。价格、概率、收益率、担保金额和覆盖股数均由 Decimal
规则代码计算，AI 不得自行补全。

默认不向外部 AI 发送账户名称、成员姓名、总资产、现金余额、完整持仓或交易历史。私人数据授权、
成本上限和留存策略必须作为本模块独立配置，不能自动沿用 AI 情报的公开摘录授权。

## 10. 首批标的

首批能力探测覆盖：

- TSLA、MSFT、AAPL、AMZN、GOOG、GOOGL、META、NVDA；
- TSM、ASML、AMD、INTC、MU；
- SKHY、SPCX。

GOOG/GOOGL 在产品配置时作为不同证券保留，后续由用户选择主要策略标的。TSM、ASML 使用美股 ADR。
SKHY、SPCX 作为“美股代码和期权链可用”的待验证假设进入 M0；只有当前 Futu 权限实际取链成功后
才进入候选范围。即使可用，也因上市历史短而必须单独显示历史覆盖不足。

## 11. 验收标准

### 11.1 产品验收

- 首页能区分“必须处理”“可比较”“暂停”和“数据不可用”。
- 每个候选显示独立收益、概率、资金和尾部风险，不只显示总分。
- 周度候选与其他 DTE 可在同一决策页公平比较。
- 财报门控、现金担保、覆盖股票和人工暂停不能被 AI 绕过。
- Roll 展示增量和累计口径，真实成交前不改变持仓或现金。

### 11.2 财务与安全验收

- 全部金额、价格、概率计算输入使用明确单位；财务计算使用 `Decimal`。
- 同一账户所有 Put 担保之和不超过已结算、未占用现金。
- 不使用其他账户、股票市值、未结算权利金或融资购买力担保 Put。
- 同一股票不能重复覆盖多个 Call；部分成交和部分指派不会重复释放资源。
- 报价、现金或关键事件数据未知时 fail closed。
- 致富证券和盈透账户容量快照分别验证身份、来源、`as_of`、已结算现金、NAV、待结算资金、融资标志
  和实际持仓；跨账户数据不能合并。
- 真实未平仓腿形成硬资源占用；候选不形成占用且明确互斥，组合选择和真实成交关联时重新原子校验。
- Covered Call 的股票分配按实际 assignment/buy lot 管理，多个批次、部分指派和部分释放不会串批。

### 11.3 AI 与审计验收

- AI 只能引用输入候选和证据，不能生成订单或交易流水。
- 保存模型、服务商、提示词、Schema、输入指纹、Token、费用和操作者。
- 重跑生成新版本，不静默覆盖历史。
- 概率预测与实际结果可回溯并按区间检查校准。
