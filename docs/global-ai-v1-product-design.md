日期：2026-09-06。状态：设计仍待整体评审；模块级只读服务、私人会话、版本化记忆、外发授权及
请求生命周期基础已建立，20案例评测器的16项当前可执行检查已通过；正式页面和模型调用未实施。

## 1. 产品目标与已确认范围

让夫妻二人在家庭工作台内，通过一个持续对话的助手查询、理解和回顾已有资料。
首个核心场景分为两类：依据本人最新正式账本资产快照概括全部账户资产；依据投资模块的
具体账户持仓，结合个人目标讨论该投资账户内部的大类配置。两类结果不默认合并。
家庭账本现金流分析与知识问答沿用同一入口，但分别调用所属模块的数据工具。

已确认：财务夫妻共享，默认本人范围，可切换全家；私人知识、对话和记忆需隔离；云端为主，
保留本地模型选择；用户愿意允许相关财务信息发送云端。该偏好不代表其他成员已完成个人资料外发授权。
个人目标为长期复合年化12%，不排除新增投入；尚未确认12%是否指剔除投入后的投资收益率，
不能擅自改为含投入的资产规模增长目标。回撤承受要求30%；先讨论股票、
债券、现金等大类比例。目标不能自动套用妻子，也不修改已有投资目标计算公式。

未确定：未来投入与大额支出、回撤计算口径、资产类别映射、负债及未录入资产覆盖、云端预算与服务商。
不能把缺失项目默认作零或认定不存在。

## 2. 第一版交付分层

| 能力 | 首版规划 | 发布门槛 |
| --- | --- | --- |
| 资产事实查询 | 按模块查询资产，标明成员/账户/日期与来源 | 模块选择、日期、汇率、完整性核对通过 |
| 知识问答 | 在有权的正式资料中检索，返回精确引用 | 检索与版本权限评测通过 |
| 现金流解释 | 指定期间收入、支出与变化，标明记录覆盖 | 使用既有服务口径，收支/转账/投入不混淆 |
| 连续对话与记忆 | 私人历史、可编辑个人背景、家庭共同记录 | 成员隔离、确认、撤销与切换测试通过 |
| 配置建议 | 保留为核心目标，独立开关 | 专项质量门槛通过后开放；当前原型未通过 |

能力未通过时不显示一个会生成任意建议的入口；可提供事实分析、缺失条件及下一步需补的信息。
知识问答不自动加入互联网搜索；主动提醒、定期财务报告、自动交易、改账、全自动资料整理不属本版。
普通 viewer 可以提问、管理自己的对话与个人背景，不能借 AI 修改业务事实。

## 3. 页面与日常流程

### 全局入口

主导航新增“AI 助手”，任意模块保留同一入口。桌面端左侧为本人对话列表，中间为对话正文，
右侧可展开数据依据；移动端列表与依据使用可返回的独立面板，不压缩正文。
运维配置与调用日志放设置区域，不占据日常聊天首页。

新对话顶部显示：财务范围“我的 / 全家”、模型、知识范围、记忆状态。
建议知识范围默认“我的资料 + 家庭共享资料”，正式归档内容可检索；待整理内容需要显式纳入并标记状态。
“全家”只控制财务查询；不隐式改变知识可见权限。对话始终显示“仅自己可见”。

空状态给三个真实问题入口：“查看我的资产配置”“解释本月收支”“在资料中找答案”。
未配置模型或未准备检索索引时明确说明准备条件，不展示示例答案作为真实结果。

### 模块内入口

资产快照页提供“根据这份快照提问”，传入快照 ID、日期和当前成员筛选；不能悄悄换到另一份快照。
账本页传入所选期间及筛选条件；知识详情传入资料 ID 与版本。
带入内容以可展开的数据范围卡显示。跨模块补充查询仍受本次范围和成员权限限制。

### 一次回答

1. 用户选范围并提问；后端记录请求与授权范围。
2. 显示“正在查询资产 / 正在查找资料”等简短进度，可停止；不展示模型私有推理。
3. 回答按需要给出结论、业务数字、依据、假设、缺口。精确金额来自程序返回的证据，不由模型心算。
4. 点击依据回到快照/账户/收支记录，或文档对应版本与段落；无权限时不提供片段。
5. 用户追问可复用上下文；动态数据有变化时标注“本轮重新查询”，历史答案不静默重算。

事实查询不必套用长篇报告模板。配置分析才展示当前比例、条件化方案、差异、依据和无法验证的风险。
“有引用”和“有免责声明”均不等于结论可靠。

### 切换与失败

切换财务范围建议创建关联的新对话，保留原会话；不在一个回答中无声改变成员集合。
切换模型保持宿主对话和已确认记忆，但每次发送前重新检查历史、摘要和引用是否允许给目标服务商。
本地断开时显示不可用，不自动将内容转发云端。云端超时保留“结果未确认、可能已产生用量”，
刷新页面仅恢复状态；重试必须创建明确的新请求，不能重放已提交的请求。

## 4. 权限、分享与记忆

| 内容 | 规则 |
| --- | --- |
| 财务 | 双方有权查询，范围按钮限定本次选择；操作者始终是真实登录者 |
| 知识 | 按来源、资料和原业务权限判断；后台管理员身份不自动扩大 AI 可读正文 |
| 对话 | 默认私人；知道会话 ID 不能读取、恢复、导出或取消他人会话 |
| 个人记忆 | 仅本人使用；风险偏好和目标不自动复制给配偶 |
| 家庭共同记录 | 双方可查看维护，保留修改者与版本；个人偏好不能自动变成共同目标 |

记忆页面包含“已确认”“待确认”及来源/更新时间；模型提取为候选，由成员接受、修改或拒绝。
成员主动编辑后生成新版本，过去引用仍指向原版本。删除后停止后续注入；删除记忆与删除原对话
是独立操作，界面解释影响，并允许阻止从原对话重新提取同一记忆。
最新余额、行情和收支不保存为静态偏好；每次使用业务查询。

建议首版支持“分享本条回答”而非整段私人对话公开：先检查引用资料和个人记忆的共享权限，
生成待预览的分享副本；含私密证据时先移除或由所有者明确发布。不能只删除引用链接却保留私密结论。
共享快照只在站内鉴权访问，不生成公开链接。来源权限撤销后，依赖该来源的共享答案暂停展示，
由所有者复核生成新的可分享版本；保留审计记录，不从备份回灌旧缓存。

云端授权按成员、服务商和数据类型持续设置，覆盖对话、检索片段、记忆、嵌入与重排。
读取权限不等于外发权限；允许范围内不逐次弹窗，增加服务商或数据范围时再确认。
身份凭据和部署秘密永不作为业务上下文。用户能查看本次发送范围与用量，费用未知就显示未知。

## 5. 本地代码查证与资产数据口径

以下为代码事实，不是生产数据审计：

| 对象/路径 | 查证结果 | 对设计的影响 |
| --- | --- | --- |
| ledger/models.py 的 BankAccount | 账户身份与归属，无实时余额字段 | 不能向账户表直接索取“最新余额” |
| AssetBalanceSnapshot / AssetBalanceEntry | 有日期、草稿、成员、账户、类别、原币与本位币金额 | 可作为正式资产快照证据；草稿不能默认入选 |
| ledger/views.py 的 overview、build_overview_asset_charts | 汇总最新正式账本快照的全部 entries | 名为 bank_total 的变量不证明内容只有银行存款 |
| portfolio/models.py 的 InvestmentAccount | bank_account 使用 OneToOneField 关联统一账户 | 跨模块身份用 ID 关联，不用账户名称模糊匹配 |
| portfolio/snapshot_service.py | 生成家庭、成员及账户层级快照，均有现金与证券明细 | 层级总额不能叠加；选一种汇总层级 |
| portfolio/historical_valuation.py | 历史估值由交易/现金状态计算；可采用同日账本快照汇率 | 投资快照不是独立于账本、可直接相加的一份银行资产 |
| ledger/asset_snapshot_import.py | 可创建停用的历史账户并保留导入明细 | 分析历史快照不能只筛当前启用账户 |

### 已确认的业务关系（用户于2026-09-05补充）

账本资产快照覆盖家庭所有账户，包括券商、银行、信用卡、支付宝、微信等。每月末由夫妻分别
查询账户实际余额后手工录入。它包含券商账户资产，不能再叠加投资快照。
投资快照仅覆盖家庭券商账户：以录入的期初余额和股票、债券等持仓为基础，结合手工记录的
买卖及出入金计算；用户说明 NAS 每天早上六点通过 Futu API 更新持仓价格。
该时间为用户描述，本轮未核验或修改生产任务；任务运行时间也不等于行情的实际估值时点。

月末两套记录允许存在小额差异。投资模块已有由管理员主动执行的“投资账户月底差额对齐”功能；
是否对齐属于投资模块管理流程，不作为全局 AI 的默认分析任务。月末账本实际余额记录用于全账户
资产分析，投资估值用于具体投资账户的持仓结构和变化。全局 AI 不主动比较、解释或修正两者差异。
信用卡账户已在覆盖范围内，但欠款/溢缴款的符号、资产与负债展示规则仍须依据实际字段核对。

### 基于上述关系的读取设计（模块级只读服务已开始实现）

用户问“根据最近一期全部资产快照”时，默认只选最新正式账本资产快照，按本人 entries 汇总；
不读取投资模块补充或校正金额。页面显示覆盖范围，不声称已覆盖未录入资产。
同日多份正式快照按日期、创建时间、ID稳定选取，同时提示存在多个版本并可切换；如果最新一期没有
本人明细，提示这一缺口并提供上一期本人数据选择，不能默认为本人资产为零。

用户问具体投资账户时，只读取投资模块中有权访问的账户、持仓、现金和估值，明确投资估值日期；
不读取账本中的相应账户余额，也不声称该结果代表全部家庭资产。账户内部的大类比例只使用投资模块
数据计算。缺价、缺汇率或未知分类时列出缺口，不用账本余额填补。

只有用户明确提出跨模块合并问题时，才进入单独的组合流程。首版不实现通用跨模块合并器；未来如需
统一展示，由用户先在投资模块完成月底差额对齐，再对指定日期、账户和范围单独验证。不能仅因两个
金额恰好相等就推断已完成对齐，也不能把少量跨模块需求变成各模块之间的默认依赖。

资产类别映射应形成小型受控表：原类别 → 大类 → 映射依据。股票/债券/现金之外保留“其他/未分类”；
负债、衍生品和负余额不强塞进三类，不删除以改善占比。无映射时可展示原分类，不输出完整配置建议。
金额/比率使用 Decimal，模型接收字符串金额；不复用图表中的 float 展示值进行财务计算。

### 接入前必须补的校验

- calculate_base_amount 在未命中已支持汇率时直接返回原金额；不能因为已有 base_amount 就认定估值完整。
  AI 读取层要核对币种、汇率、日期与来源，发现缺汇率返回原币及缺口；不在本次设计中修写历史数据。
- accessible_documents 的所有者分支不强制来源共享，accessible_search_entries 的基础查询仅按投影共享状态。
  全局 AI 读取层已经额外要求来源和资料同时对当前成员可见，并在搜索结果与精确版本读取时重新校验；
  索引只用于生成候选，不作为正文或权限事实。此结论只描述新增 AI 服务，不据此断言其他线上调用链存在泄露。
- 缺价、过期手工价、汇率缺失或估值错误要从快照审计字段携带；不存在字段不等于检查通过。
- “有正式快照”与“足够评估配置风险”是两层要求；仅一张快照无法给出最大回撤符合性的结论。

## 6. 实现边界与验收

沿用模块化 Django；ai_analysis 承担提供商接入、会话、记忆、任务状态和审计，财务计算与正式业务报告
仍由对应模块负责。先将现有页面中的可复用计算提取为只读服务再接 AI，不让模型调用任意 SQL 或 Python。
每次工具调用、异步结果保存、历史读取都复核真实成员与权限；不信任模型提出的 actor 或共享标记。

业务对话、引用和确认记忆由数据库保存；运行引擎的 thread ID 只作映射。
普通 API 是已验证的候选路径，Codex 为可选引擎；协议兼容性与身份隔离验收未完成前不设为默认。
不新增 Celery/Redis；交互任务机制需单独验证并发、超时、取消、重连、迟到结果和用量上限。

桌面/移动端、viewer/member/admin 两名真实隔离身份都要验收核心流程；测试不能仅证明页面HTTP可达。
上线前执行权限、财务计算、引用、幂等与迁移测试；投资相关生产代码改动仍遵循项目规定的测试与部署技能。

## 7. 用户评审时重点确认

1. 已确认模块独立：全部账户资产使用账本快照，具体投资配置使用投资模块；默认不比较或合并。
2. 私人对话默认不共享；首版分享单位为经过证据检查的一条回答副本。
3. 首版分能力开放，查询/知识先验收，配置建议通过专项评测后开放；不取消配置分析目标。

费用额度、模型名单与全家共同目标另行填写；未批准的默认规则不能当作生产数据变更授权。
