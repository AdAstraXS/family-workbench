# 阅读成果标准格式 v1

本规范用于本地模型制作可上传的导图和知识库。上传文件仍为一个 UTF-8 HTML，最多 5 MB。
工作台保留原件，并从下列数据块读取结构；不会执行脚本来读取数据。

```html
<script type="application/json" id="reading-artifact-data">
{
  "schema_version": 1,
  "title": "阅读方法",
  "sources": [
    {"id": "r1", "label": "第一章摘录", "quote": "在这里放入实际参考的原文。"}
  ],
  "sections": [
    {"id": "s1", "title": "核心观点", "kind": "book", "content": "纯文本总结。", "source_ids": ["r1"]},
    {"id": "s2", "title": "我的理解", "kind": "member", "content": "自己的笔记。", "source_ids": ["r1"]}
  ],
  "nodes": [
    {"id": "n1", "title": "阅读方法", "parent": "", "section_id": "s1", "source_ids": ["r1"]},
    {"id": "n2", "title": "我的理解", "parent": "n1", "section_id": "s2", "source_ids": ["r1"]}
  ]
}
</script>
```

## 字段约定

- 每个列表内的 `id` 唯一，仅用英文字母、数字、下划线、短横线，1–64 字符；修改正文时保留 ID。
- `kind`：`book` 原书观点，`member` 成员观点，`ai` AI 提炼，`external` 外部整理。
  作者自己的推断不要标成原书原话。
- `content` 为纯文本，换行直接用 JSON 的 `\n`；HTML/Markdown 均不作为富文本执行。
- `parent` 为空代表根节点，否则指向另一个节点；不允许循环，最多 20 层。
- `section_id` 指向正文小节，可留空；`source_ids` 必须引用实际存在的来源。
- 标题最多 250 字；单节正文、单条来源摘录最多 12000 字；最多 200 节、200 节点、100 条来源。
  规范化后的 JSON 总长度最多 300000 字符。
- 整个 HTML 只能有一个上述数据块。数据中的 `<` 建议编码为 `\u003c`，避免 `</script>` 提前结束数据块。
- HTML 外壳可自行排版。工作台的结构视图使用自己的安全模板；原始 HTML 另有隔离预览。

## 来源与版本

外部文件即使声明 `verified: true`、文件哈希或工作台 ID，也不会被当作已核验引用。
v1 将外部来源统一标记为“来源未核验”，不自动映射到原书；系统生成的总结保存实际输入快照，
包含文件哈希、正文处理器版本、章节/页码及批注版本，可返回依据。

成果身份、访问权限和发布版本号由服务器分配。上传时选择关联图书和可见范围。
同一作者、同一图书下的相同原件会提示重复；已有成果可“上传为新版本”，也可在页面修改小节和节点。
原版本及其知识中心归档保持不变。成果中的观点类型可随人工整理调整，来源快照保持原样。

没有此数据块的 HTML 仍可保存、预览、下载及版本化，但不承诺结构编辑。
隔离预览阻止外部资源、网络请求、表单、弹窗及访问工作台登录信息；依赖这些能力的文件可能只显示部分内容。
直接访问预览文件地址会下载原件；交互预览在工作台的受控容器内进行。

## 给本地模型的制作提示

> 请基于我提供的原书片段和个人笔记制作一个 UTF-8 单文件 HTML。包含一个
> id 为 reading-artifact-data、type 为 application/json 的 script 数据块，严格遵守
> 本规范 schema_version 1。来源摘录必须来自实际输入，不虚构引用。区分原书观点、
> 我的观点和 AI 提炼。小节、节点、来源各自使用稳定 ID，导图可点击到小节。
> HTML 自包含，不引用外网，不请求网络，不使用表单、弹窗或浏览器存储。
> 不输出 verified=true，也不捏造工作台图书、批注 ID。后续修订保留未改变条目的 ID。
