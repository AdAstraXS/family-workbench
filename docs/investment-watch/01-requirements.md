# 需求与优先级

版本 v0.4，2026-09-30。正式 Django 页面为当前实现；静态 Demo 只作历史设计参考。

## 本轮确认的使用方式

- 从关注设置、新闻关联或主题页添加公司，按名称/代码检索已有证券或新建。研究档案仅本人可见；允许先关注、后形成正式判断，不因添加公司推定持仓。
- 公司入口打开研究总览，分别列出投研证据分析、新闻证据分析及含新闻的综合分析历史；正式判断与历史保留独立入口。综合分析重新核查底层证据，不拼接两份 AI 报告。
- 规则保存前预览最近 500 份材料的匹配情况；预览不保存候选、不调用模型。暂停自动关注不妨碍阅读公司主题。
- 管理员可配置 RSS/Atom、公开 JSON、静态 HTML 和已适配网站。先测试真实读取样例，再保存为暂停来源，确认后启用。普通成员不能修改家庭共享来源。
- 相似报道提示人工复核。确认无新增信息的重复材料共用原始分析；进展、冲突分别保留。材料或原始依据改版后，关系须重新核对。
- 来源陈述、作者观点、模型推断分开存储和展示；原文引文存在不等于事实或推断正确，仍需样本验收。

## 产品目标

让成员持续了解关注公司的新事实、行业与外部环境变化，对照自己的投资假设，决定是否需要重新研究或修订判断。首例是微软，复用工作台已有研究档案。研究或关注公司不表示真实持仓。

主要用户流程：打开投资动态 → 看新增事实和对应假设 → 核对原文及分歧 → 记录待验证问题 → 必要时进入现有投研页修订正式判断。

另一个日常入口为新闻浏览：多源采集后的财经材料，经基础质量检查、宽松行业预筛和同篇去重即可展示。不以命中个人标的、AI 分析完成或证据方向明确为前提。支持市场、类别、来源、日期及搜索，默认按原始发布时间排序；未知日期独立标记，不用发现时间冒充新新闻。范围是已配置且有阅读权限的来源，不宣称全网覆盖。

## 页面职责（已确认）

| 页面 | 职责 | 约束 |
|---|---|---|
| 新闻浏览 | 日常财经阅读、发现线索、手动关联研究 | 不逐篇做个人 AI 分析；暂停个人关注不影响浏览 |
| 主题 | 按市场与资产、公司与行业、全球环境浏览新闻集合 | 数量仅统计可读材料；主题不是个人关注，不产生投资判断；空主题不填充新闻 |
| 投资动态 | 自动召回或手动关联的个人材料，逐假设影响和待复核变化 | 假设只读引用现有研究；手动关联只创建 unknown 候选，不自动成为证据或支持结论 |
| 公司研究 / AI 综合分析 | 综合财报、官方披露与选定新闻证据，评估假设、分歧和缺口 | 复用既有页面；分析绑定输入与判断版本，旧报告不被新闻静默改写 |
| 当前判断 / 判断历史 | 成员正式判断及修改历史 | 唯一正式编辑入口；投资动态不维护第二套逻辑 |
| 关注设置 | 关联词、包含/排除、启停和召回预览 | 不重新录入投资假设；关注关系不回写公共新闻池 |

旧分析之后新增的材料单独提示“尚未纳入本次分析”。成员按需重跑或已授权任务生成新的分析记录；浏览页面不触发付费。官方资料和新闻依照同一证据链去重，不能反复增加支持权重。

## 已确认约束

- 在家庭工作台内开发，复用 M4.1 通用能力和已有投研；从 AIHOT 选择性借鉴采集、宽预筛、事件整理和版本追溯。
- 投资动态原型的阅读、详情、关注设置、收藏备注继续使用。个人假设、阅读状态、备注按成员私密保存。
- 来源覆盖中美市场，允许行业、利率、汇率、政策和地缘信息不出现公司名但具有明确影响路径。
- 国内新闻优先华尔街见闻、智通财经、财新等相对重视原创与证据的媒体；官方来源用于数据、政策和公告。列入候选不等于已稳定接通。订阅受限材料显示元数据和原文入口。
- 月运行支出目标 30～60 元。先用规则宽召回、去重和缓存，少量材料深分析；总成本包含模型以外支出，必须以实际账单验收，不能仅靠调用次数声称达标。
- 不做热度榜、自动日报、自动交易、自动改写正式判断或保存到家庭知识库。精选订阅保持独立。

## 优先级

| 优先级 | 能力 | 验收标准 |
|---|---|---|
| P0 | 私密关注与研究关联 | 复用证券和研究档案；跨成员、跨家庭访问一律拒绝，管理员不绕过个人权限 |
| P0 | 新闻浏览 | 宽预筛与去重后直接阅读；未命中关注仍可见；筛选、原文入口、手动关联研究 |
| P0 | 主题目录 | 分组卡片进入主题新闻列表，支持叠加类别、日期等筛选与返回全部新闻；主题计数和列表口径相同 |
| P0 | 资料与时间 | 原文、来源、发布时间、事件时间、发现时间分开；未知时间不推测；内容版本可回溯 |
| P0 | 宽召回和反证 | 别名、关联领域、包含/排除词可解释；不因负面、低热度或旧 AI 评分而提前漏掉关键材料 |
| P0 | 逐假设证据关联 | 同条材料可对应多条假设、方向不同；区分规则候选、模型建议、成员复核 |
| P0 | 投资动态与详情 | 支持按标的、假设、方向筛选，事实/观点/推断分开；来源和证据链数量不混同 |
| P0 | 收藏、备注和版本 | 上游更新、合并、撤回不删除个人记录；正式判断更新后旧关联显式待复核 |
| P0 | 公司研究衔接 | 取消重复投资逻辑页面；从动态进入已有研究，明确新增材料与旧分析快照的边界 |
| P0 | 覆盖与费用 | 显示成功时间、失败和缺口；预算不足降级保留候选，页面浏览不调用模型 |
| P1 | 新闻事件和实质进展 | 去重、合并建议、相反解释并列；同公司不同事件不混并，转载不增加独立证据数 |
| P1 | 少量受控分析 | 一次结构化分析优先；重要、冲突或证据不足项才复核；缓存包括材料、假设和提示词版本 |
| P1 | 持续运行 | 独立定时进程，幂等、互斥、失败重试、运行记录；无变化不反复提醒 |
| P2 | 按需拓展 | 更多标的和信源、影响变化汇总、漏选抽查和规则建议；以首例验证结果决定 |

P0 是可安全使用的最低范围。当前已进入 Django 可用版实现；真实模型质量、账单和生产调度另行验收，状态以任务表和验证记录为准。

## 微软验证清单

关键假设按研究页概括为：AI 算力需求增长、资本投入转化改善、云与 AI 收入增长、估值倍数获得支撑。具体正式措辞与版本以工作台研究档案为准。

- 公司财报可支持云收入增长，不能直接证明全部增量来自 AI。
- 产品收费发布是商业化线索，不能直接证明收入、利润或资本回报改善。
- 数据中心电力、建设或供应问题可间接影响资本投入兑现；必须写出影响路径，不能只看关键词。
- 利率变化可能影响估值条件，但不能据此确定微软估值倍数的方向。
- 相反信息必须可见；缺少利用率、回报率或一致预期时标记缺口，不能填充猜测值。

## 质量验收办法

首例建立人工标注集，覆盖直接公司新闻、间接影响、无关同名、同源转载、真实后续、矛盾观点、缺日期、受限正文和来源更正。分别记录漏选、误选、错误合并、无依据推断和每条新增有效证据的调用成本。先取得基线再设质量门槛；预设百分比不当作模型成绩。
