# 在线书库：开源选型与真实样本验证

日期：2026-09-26。状态：完成第一轮调研和本地技术验证，尚未完成产品开发或上线验收。
产品范围以[需求与设计草案](reading-v1-design-draft.md)为准。

## 1. 建议采用的方案

在现有 Django 工作台中建设阅读模块，优先采用 **foliate-js 渲染 EPUB/MOBI，独立 PDF.js 渲染 PDF**。
书籍、成员权限、位置、批注、评论、计划和成果由工作台保存。
这一建议基于下面的真实样本结果；手机真机、PDF 文字划线和生产权限仍是实施门槛。

- EPUB 使用按章节/资源读取的接口。直接给 foliate-js 一个文件 URL 的默认路径会下载完整文件；
  本次验证另写资源加载器，证明可避免先下载整本 70 多 MB 的书。
- MOBI 原生阅读和锚点恢复已通过一个样本。服务端提取章节、形成稳定正文并供 AI 使用仍需验证，
  不能据此宣称 MOBI 的整个业务流程完成。暂不因一个格式就确定引入完整 Calibre 运行环境。
- PDF.js 自行接入页渲染、文字层和标注层；不使用 foliate-js 的实验性 PDF 适配承担正式 PDF 功能。
- 保留 EPUB.js 作为 EPUB 备选。只封装打开、跳转、当前位置、选中文字和高亮所需的小接口，
  不提前建设可以替换任意阅读引擎的复杂框架。
- 开源整站主要用于借鉴交互。直接部署另一套完整书库会增加账户、权限、数据和备份的衔接工作，
  对当前已有知识中心及 AI 能力的工作台收益有限。

## 2. 开源项目比较

以下能力与许可证来自项目官方仓库和文档。完整应用未逐一部署实测；本次实际运行的组件是
foliate-js、PDF.js、EPUB.js。许可证为仓库标注，正式引入时保留锁定版本及依赖的许可证和声明。

| 项目 | 值得借鉴或使用的部分 | 本项目的判断 |
| --- | --- | --- |
| [foliate-js](https://github.com/johnfactotum/foliate-js) · MIT | 浏览器阅读内核；EPUB/MOBI、定位、高亮；原生 ES 模块 | 优先候选。官方明确 API 尚不稳定且无正式 release，必须锁定提交并验证升级；PDF 支持标为实验性 |
| [PDF.js](https://github.com/mozilla/pdf.js) · Apache-2.0 | PDF 页面、文字提取、坐标和按范围加载 | PDF 首选。家庭批注、权限和服务器续读需自行实现 |
| [EPUB.js](https://github.com/futurepress/epub.js) · BSD-2-Clause | EPUB、CFI 定位和高亮接口 | 备用候选；本次仅完成打开对照，没有完整运行其批注验收 |
| [Readest](https://github.com/readest/readest) · AGPL-3.0 | 多格式阅读、笔记与高亮、阅读布局；基于 Next.js/Tauri，使用 foliate-js | 阅读器交互的重要参考；本次使用 foliate-js 上游，不将 Readest 整站或其分支直接嵌入 Django |
| [BookLore](https://github.com/booklore-app/booklore) · AGPL-3.0 | 书架、元数据、多用户、进度与导入状态 | 参考书库管理。查阅时官方已说明进入维护模式，活跃开发转向 BookOrbit，不能按旧推荐名单假定仍是主要开发仓库 |
| [Calibre-Web](https://github.com/janeczku/calibre-web) · GPL-3.0 | Calibre 书库网页管理、浏览阅读、转换和分发 | 依赖 Calibre 数据库和转换工具的路线更适合已有 Calibre 书库；当前不新建第二套书目事实来源 |
| [Kavita](https://github.com/Kareadita/Kavita) · GPL-3.0 | 响应式阅读、阅读清单、用户管理、EPUB 批注 | 参考桌面/移动端信息组织；完整阅读服务器并不直接替代本项目的成员批注与知识归档流程 |
| [Readium TS Toolkit](https://github.com/readium/ts-toolkit) · BSD-3-Clause | publication / navigator 等出版物组件和定位模型 | 更适合进一步采用 Readium 出版物体系时评估；当前主要参考定位模型 |
| [KOReader](https://github.com/koreader/koreader) · AGPL-3.0 | 原生阅读设备和外部续读生态 | 属于后续外部工具同步研究，首版浏览器目标无需接入 |

Readium 的 [Locator 模型](https://readium.org/architecture/models/locators/)将资源地址、位置与摘录上下文组合，
适合作为本项目稳定引用的设计参考。这里是借鉴字段含义，尚未声明实现 Readium 互操作协议。

## 4. 实测结果及边界

### 4.1 EPUB 与 MOBI

| 检查 | 结果 | 证明范围 |
| --- | --- | --- |
| 普通 EPUB 打开、正文和目录解析 | 通过 | Chrome 本地样本 |
| 大 EPUB 按资源读取 | 通过 | 第一次记录中书内资源响应合计 597,752 字节、16 次请求；不含目录 JSON 和引擎文件，不是全站网络流量 |
| EPUB 高亮定位 | 通过 | 两个 EPUB 将 30 字摘录转换为 CFI，再反向定位核对文字一致，并显示黄色高亮 |
| EPUB 保存位置、翻页后恢复 | 通过 | 保存与恢复后的 CFI 一致；测试保存在同一浏览器 localStorage |
| 宽度变化后恢复高亮 | 通过并有待排查告警 | Chrome 390 px / 820 px 视口，正文重排且恢复的文字一致；缩放切换出现 ResizeObserver 告警 |
| MOBI 阅读、高亮及刷新后恢复 | 通过 | 一个无 DRM 样本，恢复后 30 字摘录一致 |
| EPUB.js 对照打开 | 通过 | 普通 EPUB 初始显示，使用完整文件加载路径 |

普通/大 EPUB 的单次本地打开记录约 0.26/0.33 秒，MOBI 约 0.12 秒；EPUB.js 对照约 3 秒。
加载路径、缓存和初始化条件不同，**这些不是公平性能基准，也不用于承诺 NAS/公网速度**。

未实现真实手势选字菜单、批注数据库、评论和跨账户/跨设备同步。自动选取 30 字形成高亮
只验证锚点与覆盖层的基本能力，不能代替完整标注交互验收。

本次 Codex 内嵌浏览器解析 EPUB/MOBI 后，正文显示未完成，未定位根因；Chrome 正常。
Safari、iOS、Android 真机尚未验证。390 px 视口只证明窄屏排版，不能替代触摸、内存和系统浏览器测试。
固定实验日志区高度并补充阅读器销毁后，视口切换仍出现一次 ResizeObserver 告警，
未见该次高亮错位；正式阅读页需继续排查尺寸回调，不能直接忽略。

### 4.2 PDF

- 大 PDF 能识别 689 页、渲染首屏；第 1 页和第 20 页未提取到文字，与扫描样本相符。
  首次渲染及第 20 页提取检查记录共发送约 **2.72 MB**，没有先传完 184.71 MB。
  其中含被取消的初始 200 响应约 1.90 MB，以及 12 个 206 响应约 0.82 MB，
  因此不能描述为“所有请求均为 Range”。
- 文字 PDF 第 1 页文字为 0，第 20 页提取到 456 字符。
  文件能力应结合多页探测，AI 执行时再核验实际选中页段，避免封面导致错误分类。
- 该文字 PDF 的一次记录中，响应字节累计约 11.52 MB，超过 10.40 MB 原件。
  Range 请求、取消的初始请求和重复读取可能增加传输；不能承诺每份 PDF 都省流量。
- 坐标到 PDF 坐标再转回的数值检查通过。**尚未实现文字层选择、跨行高亮、旋转/缩放后恢复**，
  所以不能把这次结果记为 PDF 批注通过。

正式实现参照 [PDF.js FAQ](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions)：
服务器应正确支持字节范围请求，客户端只渲染需要的页面，避免同时保留整书画布。
实际 NAS 反向代理、鉴权后的 206/416、断连恢复和内存还需另测。

### 4.3 外部 HTML

两份用户文件完全相同，导图与知识库是一个页面中的两种视图。
本地隔离 iframe 中实际完成：首页 → 全书思维导图 → 指定章节笔记，以及搜索“国家能力”并展示结果。
这些内部链接指向整理笔记，尚未建立原书位置对应关系，来源仍应标为未核验。

单独制作的隔离探针验证了三点：访问父页面 DOM 被阻止、localStorage 被阻止、fetch 被 CSP 阻止。
配置为 iframe `sandbox="allow-scripts"`，响应同时添加 CSP `sandbox allow-scripts`，
不授予 same-origin，禁止网络连接、表单和默认外部资源。机制可参考
[MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)。

用户样本主要导航、搜索可以运行；其主题保存不能沿用宿主 localStorage。
打印、任意外链/附件、所有浏览器和其他 HTML 尚未验收。
探针只覆盖上述三个边界，不等于完成 HTML 安全审计。

## 5. 对现有项目的具体影响

### 5.1 已有能力可以复用，但需要区分用途

检查了 `app/knowledge/storage.py`、`artifacts.py`、`models.py`、`permissions.py`、
`views.py` 和 `app/templates/knowledge/artifact_detail.html`：

- 已有受保护存储，以及成果原文件、版本、引用证据和隔离预览能力。
  原先“只有正文净化，需要完全新建 HTML 预览”的判断应修正为复用现有成果机制。
- 现有成果创建按“家庭 + 人物名称 + 成果类型”定位，不能直接用于每本书的成果，
  否则同类型读书成果可能错误合并。阅读成果以图书/作者/成果 ID 定位，归档时再建立知识投影。
- 现有引用识别服务面向人物文章和特定 HTML 数据结构，不能直接识别任意 EPUB CFI 或 PDF 原文页段。
- 当前 HTML 预览有 iframe sandbox 和严格 CSP；新阅读成果入口还应验证直接打开渲染 URL 的隔离，
  本实验增加了响应级 sandbox。这里记录接入要求，未改动已有生产预览代码。
- 现有成果上传限制为 5 MB；书籍上传独立配置限额，不能为了大 PDF 放宽所有知识资料的限制。

### 5.2 文件与引用

建议保留不可变原件、SHA-256、规范化正文修订号和处理器版本。EPUB 原始内容与用于阅读的安全内容
分开；规范化不得在已有批注后静默重做。正式上传需限制解压总量、文件数量、单资源、路径和处理时间。

定位记录按格式保留：

- EPUB/MOBI：文件/正文修订、章节 href/索引、CFI、摘录及前后文。
- PDF：文件身份、页码、规范化区域、摘录及上下文，保留旋转/坐标约定。
- 标准成果：成果版本、小节/节点稳定 ID、引用类型及核验状态。

位置是精确引用，进度是估计值，完成是本人确认，三者分开存储。
跨设备写入带服务端 revision；旧设备写入发生冲突时应提示采用哪个位置。
不把最高进度当作最后位置，也不在后台直接合并成员阅读轨迹。

EPUB 不执行书内脚本。foliate-js 上游特别提示同源 blob 与 WebKit iframe 限制，
仅加一个 sandbox 属性不足以保证安全；生产必须验证服务端净化、CSP、外部资源限制和文件访问权限。
实验读取的是选定样本，不代表可直接接收任意不可信 EPUB 上线。

### 5.3 TXT / MOBI 和后台处理

TXT 目录中没有真实样本，尚未验收。建议解码后按固定规则生成安全段落并保留段落 ID，
编码不明确时让上传者预览选择，目录识别失败时允许按文字范围总结。

MOBI 已证明可在浏览器直接阅读，但服务端稳定正文提取尚未验证。
若最终选择 [Calibre ebook-convert](https://manual.calibre-ebook.com/generated/en/ebook-convert.html)，
必须验证转换质量、章节锚点和 NAS 镜像依赖；当前 Python 镜像不含 Calibre，不能当作已有能力。
DRM、损坏文件和转换失败显示明确原因。

处理任务沿用项目的数据库任务记录、Django 管理命令和 DSM 调度原则；不因 50 本初始规模引入 Redis/Celery。
上传、解析和正文可用分别记录状态，能力包括可阅读、可文字划线、可供 AI 处理，
每项可独立失败并说明原因。

### 5.4 外部标准成果的下一步

首版建议先支持 **单 HTML 内嵌有版本号的 JSON**，结构数据和原 HTML 一起保留，
工作台用自己的模板展示有效结构。ZIP 多资源打包保留为后续选择，减少第一版导入分支。
这是本次实现建议，不改变兼容现有 HTML 的已确认范围。

规范至少含 `schema_version`、成果 ID、修订 ID、书籍信息、小节、导图节点、引用和制作信息。
正文以受控 Markdown/纯文本表达；节点通过稳定 ID 引用小节，原书引用和外部整理链接区分。
解析 JSON 不执行 HTML 脚本；模型填入的 ID、权限与“已核验”字段都不能替代服务端检查。
没有规范 JSON 的文件继续使用隔离预览，不声称可结构化编辑。

## 6. 后续开发顺序与通过条件

### M1：书架到真实续读

实现受保护上传、解析状态、书架与继续阅读、图书详情、阅读器、个人位置和进度。
同时建立文件、章节和稳定引用模型，补齐 PDF 文字层验证，避免后续批注返工。

通过条件：大文件实际网页上传；EPUB 按章节读取；PDF 鉴权后 Range；两设备续读与旧位置冲突；
私密文件及章节接口隔离；Chrome/Edge 与 iOS Safari/Android 真机至少各一条完整阅读流程。
若真机暂不可用，应单列未验收，不能用缩小桌面窗口代替。

### M2：批注、讨论和个人计划

实现 EPUB / 文字 PDF 划线、批注和显式分享、作者编辑自己的内容、评论；个人多书计划、
目标日期、纸质/外部阅读记录和本人确认完成。共读计划保持不在首版。

通过条件：刷新、调字号和跨设备后高亮能恢复；分享/撤回后所有入口权限一致；
评论不泄露私密书或批注；计划与估算阅读进度、本人确认互不混淆。

### M3：阅读成果和章节 AI

先接入外部 HTML 兼容预览、标准格式导入、成果版本及手动归档，
再接入选定章节/小节/个人批注总结与带依据的导图。

通过条件：HTML 隔离测试；重复文件提示；无依据结果显示未核验；
AI 逐次确认范围、模型和预计用量；引用能回到实际输入版本；失败/取消可见；
归档后权限和发布版本固定。整书生成、OCR、持续问答、跨书比较保持延期。
