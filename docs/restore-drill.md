# 隔离恢复演练

## 已有能力

`scripts/run_restore_drill.py` 在本机创建专用 PostgreSQL 容器，网络为 `none`，不开放端口。
校验容器只连接这个数据库；应用、基线与附件以只读方式挂载。完成后停止本次创建的容器。
需要当前应用镜像、已验证的 PostgreSQL dump、备份时的六张财务表计数和最新快照日期、
知识文件及媒体副本。加密密钥仅通过 `KNOWLEDGE_TOKEN_ENCRYPTION_KEY` 进程环境传递。
输出为不含原文、账号和密钥的五项 JSON 结果。任何失败或未验证项均返回非零退出码。

管理员可以在“运行监控 → 恢复验证记录”上传这份结果；普通成员可以查看。
登记结果不会执行恢复。重复上传同一份报告不产生重复记录。

## NAS 一次性演练方案（尚待管理员执行）

现有部署包装器允许生成和验证备份，但不允许读取 root 私有备份、复制知识文件或启动演练容器。
因此保留现有权限边界，提供 `scripts/nas_restore_drill.sh` 供管理员审核并交互执行，
不修改 sudoers，不开放任意 Docker，不导出生产密钥，也不把生产资料下载到个人电脑。

脚本不接受参数，源路径固定为 `/volume1/docker/family-workbench`。它会：

1. 读取基线，调用已有包装器生成一个新的数据库备份。
2. 在 `backups/drill-<时间>-<随机标识>/` 创建权限为 0700 的知识文件与媒体副本。
3. 再次核对财务基线；期间发生变化即停止，保留恢复点供检查。
4. 使用 NAS 已有镜像，在无网络、无公开端口的独立容器恢复备份。
5. 核对数据库、外键及当前版本关系、文件哈希和密文解密；仅输出汇总结果。
6. 停止本次演练容器，保留备份和附件副本。不会启动生产估值、修改生产业务记录或登记报告。

执行前先部署包含 `verify_restored_workbench` 的应用版本，并核对脚本 SHA-256。
管理员通过既有交互式 SSH 登录执行已审阅脚本；不要把密码交给脚本。
至少预留数据库备份与全部附件副本的空间，建议在采集任务空闲时执行。
文件若在复制期间被修改或清理，校验会报告失败，须保留报告并重新选取安静时间。
备份和副本由 root 私有保存，不自动清理；清理由管理员另行决定。

脚本仅将紧凑 JSON 校验报告导出为部署用户可读的私有回执，用于在网页登记。
备份、附件和密钥不导出。生产备份实际演练通过之前，
不得用本机演示数据的通过结果替代生产恢复验证。
