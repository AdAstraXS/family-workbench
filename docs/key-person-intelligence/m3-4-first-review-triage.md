# M3.4 首轮候选复核与降噪

## 目标

首次接入 RSS 时会回溯最近一批公开内容。它用于验证信源、门控和去重，不应把几十条历史候选变成
家庭成员的逐条待办。本阶段为管理员提供一个独立的“候选复核”工作台，把首轮积压与日常信息流分开。

## 页面与范围

- 入口：AI 情报 → 候选复核（仅家庭管理员）。
- 对象：当前家庭、未合并、`待复核 + 待复核展示层` 的人物情报事件。
- 筛选：关键词、主题、事件类型、主来源等级。
- 排序：来源等级 A→D、重要性、置信度、发生时间。先处理高可信直接来源，再看媒体发现线索。
- 批量操作：最多 50 条候选可明确选择“保留到全部动态”或“移入噪音箱”。每条事件保留原始证据，
  并更新既有的更新人和更新时间审计字段。

## 确定性建议

建议只帮助排序，不会自行写入事件。

|条件|建议|实际效果（仅在管理员勾选并提交后）|
|---|---|---|
|A/B 级来源、重要性 ≥ 50、置信度 ≥ 70|建议保留到全部动态|复核状态改为“已复核”，展示层固定为“全部动态”|
|D 级来源，或重要性 < 45 且置信度 < 70|建议移入噪音箱|复核状态改为“已忽略”，展示层为“噪音箱”|
|其余候选（尤其 C 级媒体）|需要单项确认|维持待复核，先查看标题、短摘录和原文|

批量保留不会因既有评分自动进入“今日精选”。“今日精选”、知识归档、已读、收藏以及 DeepSeek
分析都继续要求单条明确操作。

## 边界

- 不调用文本 AI，不发送新增外部请求，不创建定时任务。
- 不改写证据、来源条目、评分特征或事件合并关系。
- 普通成员不能访问工作台或发起批量操作；跨家庭事件不会被查询或修改。
- 该工作台解决的是首轮和异常积压的处置效率，不替代日常增量质量验收。

## 验收

- A/B 级高置信候选排在媒体候选之前，并显示“建议保留到全部动态”。
- C 级媒体候选显示“需要单项确认”。
- 批量保留不会进入“今日精选”；批量忽略后原始 `SourceItem` 和证据仍存在。
- 非管理员与其他家庭均不能批量修改候选。
- 首轮复核后仍需运行一次手工增量采集，确认候选量、去重和门控稳定，才评估 DSM 定时任务。
