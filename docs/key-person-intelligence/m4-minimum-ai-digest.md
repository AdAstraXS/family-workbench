# M4 最小可用 AI 情报闭环与每日简报

状态：已完成本地验收并部署 NAS；待少量真实 DeepSeek 候选验收
更新时间：2026-08-22

## 1. 本轮目标

本轮先把 AI 情报做成一个功能完整、规模受控的可用产品，而不是先追求大量信源：

1. 从已经验证的公开 RSS 信源采集最新条目；
2. 由代码规则完成标题命中、相关性门控、确定性评分和初步去噪；
3. 管理员从当日候选中一次选择最多 5 条，明确确认后才调用已配置的文本 AI；
4. AI 输出中文摘要、重要性说明、事件类型、事实/观点/数字和证据引用；
5. 管理员在候选复核页决定进入“今日精选”“全部动态”或忽略；
6. 系统按确定性规则生成站内每日简报，家庭成员可以直接阅读最终结果；
7. 重要长文仍由成员主动“保存为知识”，先进入知识中心的归档资料，再决定是否整理为精选知识。

首版完成以后，再逐步增加 YouTube、SEC、机构信件和其他媒体，并根据真实误报、漏报数据调整
新闻选取规则、来源权重和排序。新增来源不改变上述人工授权、证据和审计边界。

## 2. 当前首批信源

当前生产已登记并启用以下容易稳定读取的公开 RSS：

- OpenAI 官方新闻：一手事实来源，按 A 级信源处理；
- CNBC Technology：媒体发现源，按 C 级信源处理；
- TechCrunch AI：媒体发现源，按 C 级信源处理。

代码也支持其他已登记 RSS。YouTube Atom 因真实请求返回 404 继续保持停用，不阻塞首版闭环；后续
单独评估官方 Data API、配额、鉴权和 NAS 可达性，不以绕过平台限制的抓取方式替代。

## 3. AI 调用边界

- 页面 GET、普通采集、候选复核和简报生成均不会隐式调用 AI。
- 只有家庭管理员可发起批量 AI 整理；每次最多 5 条。
- 发起前页面展示服务商、模型、单条和整批最坏费用上限。
- 只发送公开标题、短摘录和来源编号，不发送家庭知识、评论、收藏、账户或财务数据。
- 每条事件沿用版本化 `EventAnalysis`、输入指纹和 `AiAnalysisRequest` 审计；相同输入默认复用，
  不重复付费。
- 单条失败不阻止同批其他条目完成，失败原因进入运行审计且不泄漏 API Key。
- AI 只提出结构化结果和评分特征，不自动发布、不自动合并事件、不自动归档知识。

## 4. 每日简报规则

每日简报不再调用 AI，只采用当天事件的“当前成功分析”，并按人工复核结果分组：

- 今日重要：已复核并进入今日精选，最多 5 条；
- 值得跟进：已复核并进入全部动态，最多 7 条；
- 待确认：AI 已整理但尚未人工处置，最多 8 条，仅管理员可见。

组内按重要性、置信度、事件时间和主键稳定排序。简报按家庭和日期唯一；相同输入重复生成会复用
现有简报。每个条目固化当时的标题、摘要、重要性说明、证据引用、分数、来源、模型、Token 和
费用快照，后续重新分析不会静默改写已经生成的历史简报。

管理员可在网页显式生成或更新当日简报。管理命令：

```text
python manage.py generate_intelligence_digest --family-id <家庭ID> [--date YYYY-MM-DD]
```

该命令只编排已有分析，不读取 API Key、不调用外部网络，可供后续 DSM 定时任务使用。本轮不自动
创建 DSM 任务；应在生产部署、人工闭环和增量采集均验收后再确认执行时间。

## 5. 权限与页面

- 管理员：查看当日候选、选择模型、批量 AI 整理、进入候选复核、生成简报、查看待确认组。
- 普通成员：只查看已经人工复核并进入“今日重要”或“值得跟进”的简报条目。
- 所有成员仍可进入事件详情、查看原始来源，并按既有权限进行已读、收藏和保存为知识。
- 不把信源状态和运维日志放到普通成员的阅读主流程；这些信息继续留在信源和流水线管理页。

## 6. 首版验收标准

- 至少一个真实 RSS 批次能产生候选，代表候选可用正式 API Key 完成 AI 整理；
- AI 结果包含可回指来源的摘要和证据，失败时安全降级；
- 管理员可复核分层，普通成员看不到尚未确认的内容；
- 当日简报可重复生成且不重复调用 AI，历史条目为快照；
- 批量上限、家庭隔离、管理员权限、成本审计和 GET 不联网均有自动测试；
- 桌面和手机页面通过登录态浏览器验收；
- NAS 部署前验证数据库备份，部署后核对迁移、关键数据基线、内外访问和实际运行提交。

## 7. 后续渐进优化

首版真实运行一段时间后，以误报、漏报和用户保留行为为依据逐项优化：

1. 增加 YouTube、SEC、机构信件、正式访谈和更多财经媒体；
2. 为科技公司、投资人物、政策人物分别建立发现规则，避免共用一套标题门控；
3. 调整来源等级、人物命中、事件类型、时效性、重要性和置信度权重；
4. 建立小规模固定评估集，对每次规则或模型变化回放比较；
5. 候选质量稳定后，再讨论定时采集、批量分析策略和站外推送。

每次只调整少量来源或规则，保留策略版本和运行审计，不能用扩大抓取量掩盖筛选质量问题。
