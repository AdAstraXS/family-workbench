# M3.1 事件结构化分析设计与验收

状态：Implemented locally

更新时间：2026-08-16

## 1. 本段目标

M3.1 在 M2/M2.6 已完成的来源保存、确定性去重和相关性门控之后，为管理员明确选择的候选事件执行
一次版本化文本 AI 分析。它解决“快速读懂候选并核查证据”的问题，不负责自动发布、自动归档、
自动合并事件或生成买卖建议。

本段遵循以下边界：

- GET 页面不调用外部模型、不创建分析记录。
- 只有家庭管理员可以在事件详情页显式发起分析。
- 发送范围仅为事件标题、关注对象、时间和最多 8 个已保存来源的公开标题与短摘录。
- 不发送付费全文、Cookie、API Key、家庭知识正文或其他家庭的内容。
- AI 只输出结构化摘要、证据引用和独立特征；最终分数与展示层级仍由 `people-v1` 代码计算。
- AI 失败、Key 缺失或结构校验失败时，原始事件和证据继续可用。

## 2. 版本化数据

新增 `EventAnalysis`：

- 关联事件、`AiProvider` 和 `AiAnalysisRequest` 审计记录；
- 保存实际模型、Prompt 版本、Schema 版本和输入指纹；
- 保存不含正文的输入审计快照、结构化结果、Token、状态和脱敏错误；
- 同一事件最多一个 `is_current=True` 的当前版本；强制重跑创建新版本，不覆盖历史；
- 相同输入、服务商、模型和版本重复提交时复用当前结果，不重复调用或收费；
- 新证据进入事件或管理员手工编辑事件后，旧分析保留历史但自动失去“当前”状态。

## 3. 强制输出结构

模型只能返回 JSON 对象，主要字段为：

- `summary` 与 `summary_evidence_refs`；
- `why_it_matters`；
- `facts[]`：每项事实必须引用输入中的来源 ID；
- `opinions[]`：必须写明观点主体并引用来源；
- `numbers[]`：保留值、单位、上下文和来源；
- `uncertainties[]`：证据不足、冲突或正文缺失的事项；
- `event_type` 与 `change_type`：只能使用系统枚举；
- `features`：0–100 的人物相关性、实质性、新颖性、潜在影响、投资参考价值和证据清晰度。

服务端拒绝不存在的来源引用、越界分数、未知枚举、自由文本或无法解析的 JSON。来源中的提示词注入
只被视为待分析数据，模型不得据此调用工具、改变规则或补全外部事实。

## 4. 评分与展示

- `subject_relevance`、`potential_impact`、`novelty`、`investment_relevance` 分别映射到现有事件特征。
- `evidence_clarity` 只作为提取确定度参与置信度；来源等级、证据完整度和独立来源数量仍由代码取得。
- `substantiveness` 保存为分析与评分解释，不让模型直接决定精选。
- 自动采集候选仍保持待复核；M3.1 不因模型给出高分而自动发布。
- 事件详情把 AI 结果与原始候选说明分开，显示模型、版本、来源数量、事实、观点、数字和不确定项。
- 归档到知识中心时固化当前 AI 分析版本、证据引用和原始候选说明；后续重跑不会改写已归档版本。

## 5. Provider 与运行状态

继续复用 `AiProvider`，只接受启用的 `openai` / `openai_compatible` 文本模型，并排除 IPO 图片识别
用途。Key 必须由 `extra_data.api_key_env_var` 指向环境变量，不得写入数据库或浏览器；即使已有 Key，
还必须显式设置 `extra_data.allow_intelligence_analysis=true`，避免知识整理模型被跨模块自动复用。

当前本地登记的“DS文本整理”既未授权用于 AI 情报，也没有在容器内配置
`KNOWLEDGE_TEXT_AI_API_KEY`。因此页面显示“1 个文本模型登记、0 个具备 Key”，分析按钮保持不可用；
本阶段没有发出真实云端请求或产生费用。

## 6. M3 后续段

M3.1 不表示整个 M3 完成。下一段按以下顺序推进：

1. 选择并配置一个正式文本模型，确认数据留存、单次输入上限和费用上限。
2. 从 11 条真实媒体候选中挑选代表样本，人工确认期望摘要、引用和特征后执行真实分析。
3. 增加“可能为同一事件”的跨来源候选判断；AI 只能提出合并建议，管理员确认后才真正合并。
4. 合并时选择等级更高、内容更完整的主来源，同时保留全部证据和拆分能力。
5. 积累可比历史后再启用延续、增强、弱化或转向判断；证据不足固定为“无法判断”。

## 7. M3.1 验收标准

- 迁移可在空库和现有库执行，不修改既有事件、来源或知识归档。
- 成功分析生成 `EventAnalysis`、`AiAnalysisRequest` 和 `AiAnalysisResult` 三层审计记录。
- 伪造引用、非法枚举和越界分数被拒绝，事件正式摘要与原始证据不被覆盖。
- 相同输入默认复用；显式重跑生成新版本且只保留一个当前版本。
- 新证据和人工编辑使旧分析失效，但历史仍可查看。
- 普通成员和只读成员不能调用模型；GET 页面不联网。
- AI 版本可以随成员主动归档操作固化到知识中心，不自动进入待整理或精选知识。
- 情报、知识联合测试、全项目回归、迁移检查和登录态浏览器验收通过。
