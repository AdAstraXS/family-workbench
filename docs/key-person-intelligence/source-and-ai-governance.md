# 关键人物动态模块：信息源与 AI 治理规范

状态：Draft 0.1

## 1. 目标

本规范确保系统中的“事实、观点、推断”可以区分，重要结论可以追溯，并让信息源中断、平台限额或
AI 出错时仍然安全降级。

## 2. 信息源等级

| 等级 | 定义 | 示例 | 使用规则 |
|---|---|---|---|
| A | 当事人、机构或监管方的一手材料 | 官方账号、公司新闻室、SEC 披露、官方演讲视频 | 可作为主要事实证据，仍需区分宣传性表述与可验证事实。 |
| B | 当事人的直接采访、演讲或完整文字记录 | 权威媒体完整采访、会议演讲、播客原片 | 可作为本人观点证据；剪辑片段需回到完整上下文。 |
| C | 有编辑责任的可信二手报道 | 主流财经、科技媒体的署名报道 | 用于补充背景和交叉验证，不替代可取得的一手材料。 |
| D | 线索与评论 | 聚合转载、匿名爆料、二次解读 | 仅用于发现候选事件，默认不生成高置信度正式结论。 |

来源等级不是永久“真伪标签”。同一来源中的具体条目仍需检查作者、发布时间、上下文和证据。

与参考文章的 T1/T1.5/T2 对照：官方官网和正式监管材料通常属于 A；官方社交账号仍属于一手来源，
但因消息更杂，可在 A 内设置较低的载体权重；完整直接采访属于 B；个人账号、KOL 和媒体根据直接性
与编辑责任落在 B/C/D。来源等级与载体权重分开保存，避免为了细分而混淆可信度和信噪比。

## 3. 平台接入原则

### 3.1 X

- 仅使用正式 X API 或人工提交链接，不依赖未授权页面抓取。
- 正式 API 的 recent search 可检索近期帖子，完整历史访问权限不同，因此系统必须用增量游标持续采集，
  不能假设随时可回补全部历史。
- 保存帖子 ID、作者、发布时间、文本必要片段和原链接；遵循平台对内容保留和删除的要求。
- X 适配器是可选能力。未取得凭证或成本不可接受时，不阻塞 RSS、YouTube、SEC 和人工来源上线。

官方参考：[X Search Posts](https://docs.x.com/x-api/posts/search/introduction)、
[X API Rate Limits](https://docs.x.com/x-api/fundamentals/rate-limits)。

### 3.2 YouTube

- 优先关注已确认的本人、公司或会议官方频道。
- 保存视频 ID、频道、标题、简介、发布时间和链接；字幕/转录文本的取得和使用必须符合接口与版权规则。
- 对固定频道优先使用频道上传列表或低成本增量方式，避免反复关键词全网搜索。
- 搜索与读取接口存在配额，应记录请求量并设置轮询间隔。

官方参考：[YouTube Data API](https://developers.google.com/youtube/v3/docs)、
[Search: list](https://developers.google.com/youtube/v3/docs/search/list)。

### 3.3 SEC EDGAR

- 用于美国上市公司、机构和投资管理人的公开披露线索，例如 13F、13D/13G、8-K 等。
- 按 SEC 要求设置明确 User-Agent、控制请求速率、使用增量更新时间和官方 JSON 数据。
- 披露事实与“投资人个人观点”分开标注；机构申报不等于个人实时交易意图。

官方参考：[SEC EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)。

### 3.4 官方网站、RSS、播客与媒体

- 优先公开 RSS/Atom、新闻室和公开 API。
- 没有许可时不存完整版权正文；保存标题、作者、时间、链接和必要短摘录。
- 同一报道的转载使用 canonical URL、来源名和内容指纹合并。
- 页面结构变化导致解析失败时停止该来源并提示管理员，不盲目扩大抓取范围。

### 3.5 人工录入

人工入口用于：

- 平台不提供稳定接口；
- 用户看到一篇重要采访或文章；
- 自动系统无法安全取得正文；
- 需要补充事件背景或纠正错误聚类。

人工录入必须记录操作者和原始链接，不能把人工判断伪装为外部原文。

## 4. 证据规则

每个事件的正式摘要拆成独立 claim：

```json
{
  "claim_id": "c1",
  "claim_type": "fact",
  "text": "某人在某次采访中表示……",
  "evidence_refs": ["source-item-123"],
  "confidence": 0.91
}
```

规则：

1. `fact` 必须至少绑定一个证据。
2. `opinion` 必须说明是谁的观点，不能写成客观事实。
3. `inference` 必须以“可能、推测、需要继续观察”等方式展示。
4. 关键数字保留原币种、单位、期间和上下文。
5. 来源冲突时并列展示，不由 AI 私自选择“真相”。
6. AI 无法确定事件发生时间时，不得用采集时间冒充发生时间。

## 5. 变化信号规则

变化检测只能比较可比对象：同一人物、同一主题、相近语义层级的历史观点或行为。

| 标签 | 定义 |
|---|---|
| 新动向 | 历史中没有足够可比事件。 |
| 延续 | 方向和强度基本一致。 |
| 增强 | 方向一致，但承诺、措辞、金额或时间表明显加强。 |
| 弱化 | 方向一致，但承诺、措辞或资源投入减弱。 |
| 转向 | 方向出现实质性反转，且有明确前后证据。 |
| 无法判断 | 历史证据不足、语境不同或来源冲突。 |

“转向”属于高影响标签，默认进入人工复核后才在首页突出展示。

## 6. AI 输出治理

### 6.1 强制要求

- 使用版本化提示词和 JSON Schema。
- 输入中给每个来源分配稳定引用 ID。
- 输出引用只能来自输入 ID，服务端拒绝不存在的引用。
- 温度和随机性保持较低，优先一致性和可审计性。
- 记录模型、服务商、提示词版本、Schema 版本、Token 和处理时间。
- 重跑生成新版本，不静默覆盖旧结果。
- 低成本模型只做相关性门控；分析模型只输出独立特征，最终权重和阈值由代码处理。
- 用户反馈进入冻结评估集，不自动增长 Prompt 或在线修改评分策略。

### 6.2 禁止行为

- 不让模型自行“浏览互联网”后返回无链接结论。
- 不使用模型记忆补全当前职位、价格、持仓或政治身份。
- 不把情绪分类等同于股价方向。
- 不根据单一人物发言生成确定买卖建议。
- 不把来源缺失或接口失败解释为“没有发生新事件”。

### 6.3 人工复核触发条件

- 重要性高且置信度低；
- “转向”或重大政策/投资动作；
- 来源之间存在明显冲突；
- AI 引用校验失败；
- 涉及金额、持仓、日期但证据不一致；
- 来源等级只有 D。

## 7. 推荐排序的可解释性

事件排序可由以下特征组成，但页面同时显示入选理由：

- 关注关系和关注优先级；
- 对象重要性；
- 事件类型；
- 新颖度和变化强度；
- 来源等级和独立证据数量；
- 发布时间衰减；
- 用户已读、静音和重复曝光状态。

模型只负责提取特征，最终分数由服务端规则计算并可测试。

## 8. 数据保留与隐私

- 原始来源条目保存必要元数据和短证据，不默认镜像完整文章。
- API 密钥、Cookie、登录状态和授权令牌不进入数据库与 Git。
- 原始响应如因调试短期保存，应脱敏、有期限并位于不提交的本地目录。
- 用户的关注、收藏和已读数据按家庭成员权限保护。
- 删除或停用来源时保留已用于历史事件的最小证据，以维持审计链；如平台条款要求删除则按条款处理。
