# 关键人物动态模块：实施路线图（Implementation Roadmap）

状态：M1、M1.5 已完成；M2 本地开发完成，待真实来源与 NAS 验证
执行原则：分阶段交付，每个阶段通过质量门后再进入下一阶段。

## 1. 阶段总览

| 阶段 | 目标 | 主要交付物 | 退出条件 |
|---|---|---|---|
| M0 | 方案冻结与来源验证 | PRD、TDD、来源清单、低保真页面结构 | 用户确认范围、首批对象和来源优先级 |
| M1 | 领域底座与人工闭环 | Django app、模型、迁移、后台、人工事件、基础页面 | 不依赖外部 API 即可完整录入和查看事件 |
| M1.5 | 信息架构与评分基础 | 信源地图、多主题关联、代码评分、展示分层、流水线统计 | 无外部 API 也可验证整理和筛选规则 |
| M2 | 自动采集与去重 | RSS、YouTube 元数据适配器、运行记录、幂等命令 | 固定样本已通过；办公电脑与 NAS 真实来源验证后退出 |
| M3 | AI 结构化分析 | AI 网关、Schema、证据绑定、重要性/置信度、变化检测 | AI 失败可降级，高风险内容进入复核 |
| M4 | 产品化页面与简报 | 今日简报、时间线、筛选、收藏、运行状态 | 桌面/手机可用，权限和全项目测试通过 |
| M5 | 可选平台与外部推送 | X API、邮件/Telegram/企业微信等可选适配器 | 单独确认成本、权限和推送策略后实施 |

M0–M4 构成建议的 MVP。M5 不自动进入开发范围。

## 5. M2：自动采集、标准化与去重

### 适配器优先顺序

1. RSS/Atom。
2. YouTube 官方频道。
3. SEC EDGAR（顺延后续阶段，不属于本轮 M2）。
4. X API（仅在凭证和成本确认后）。

### 工作项

- [x] 统一来源适配器协议和安全 HTTP 客户端。
- [x] URL 规范化、外部 ID 去重、内容指纹。
- [x] `collect_intelligence_sources` 管理命令。
- [x] CollectionRun 和按来源运行明细。
- [x] ETag / Last-Modified 游标、超时、有限重试和失败退出码。
- [x] 规则式相关性门控与事件候选聚类。
- [x] 低相关条目保留在噪音箱；候选事件强制进入待复核。
- [x] 网页显式手动采集、运行状态和失败提示；GET 不联网。
- [x] 首批 7 个官方 RSS / YouTube 信源幂等登记命令。
- [x] 办公电脑已验证 OpenAI 官方 RSS，真实采集 10 条并完成规则处理。
- [ ] YouTube 真实样本：官方频道页声明 Atom 地址，但 4 个已核对频道均返回 HTTP 404；种子配置默认停用。
- [ ] NAS 完成相同真实来源验证并配置 DSM 定时任务。
- [x] M3.3 已实现跨来源事件分级建议、批量/单项确认、主来源选择和可逆拆分；语义自动聚合保持关闭。

### 质量门

- 至少两类自动适配器通过真实样本和固定 fixture 测试。
- 同一批数据连续运行三次，条目和事件数量保持稳定。
- 401/403/429/超时/无效 XML 等错误均有明确状态且不泄漏密钥。
- 单一来源失败不阻止其他来源成功落库。

固定 fixture 已满足两类适配器、连续三次运行幂等、安全错误和故障隔离要求；真实 RSS 已通过。
YouTube 仍未通过无登录后端真实读取，不能用固定测试替代。办公电脑成功也不能替代 NAS 网络验证。

## 6. M3：AI 结构化分析与变化检测

### 工作项

- 扩展 AiProvider 的文本模型使用约定，不破坏现有视觉识别。
- 建立文本 AI Gateway，支持现有服务商多选和环境变量密钥。
- 定义 `people_event_v1` JSON Schema 和版本化提示词。
- 建立 `ScoringPolicyVersion`、冻结评估集和历史样本回放。
- 事实、观点、推断、数字和证据引用校验。
- 重要性与置信度规则计算。
- 历史事件检索和变化标签。
- 待复核队列、人工确认和重新分析。
- Token、成本和失败审计。

### 质量门

- 所有正式事实都有有效 evidence ref。
- 模型返回无效 JSON、虚构引用或超时时安全失败。
- “转向”事件默认需要人工复核。
- 切换模型不会覆盖历史分析结果。

## 10. Definition of Done（完成定义）

每个工作项只有同时满足以下条件才算完成：

- 需求和异常路径已实现，不只完成“正常演示路径”。
- 模型变化包含迁移、后台/页面展示和针对性测试。
- 外部请求有超时、限速、重试边界和脱敏错误。
- 写入操作可审计；批处理命令幂等。
- 桌面与手机页面完成真实浏览器检查。
- `manage.py check`、相关测试和 `git diff --check` 通过。
- 没有提交 `.env`、API Key、抓取原文、数据库或本地输出。
- 文档同步更新，已知限制写入交付说明。

## 11. 分支与跨电脑转移

当前独立开发目录：

```text
C:\Users\Administrator\Documents\family-workbench-key-person-intelligence
```

当前分支：

```text
codex/key-person-intelligence
```

设计或代码完成并推送 GitHub 后，家中电脑可在最新 `master` 上执行：

```bash
git fetch origin
git switch master
git pull --ff-only origin master
git merge --no-ff origin/codex/key-person-intelligence
```

如果家中电脑的 `master` 已继续开发且出现冲突，应先在功能分支合入最新 `master`、解决冲突并跑完整测试，
不要用强制覆盖或复制整个数据库目录的方式转移。
