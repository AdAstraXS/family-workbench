# M4.1 自动情报循环与公开证据摘录

状态：本地实现完成，待 NAS 首轮真实运行与定时任务验收
更新时间：2026-08-22

## 1. 用户可见结果

M4.1 把原先“采集一次、管理员选候选、调用 AI、逐条复核、再生成简报”的日常流程改为后台自动循环：

1. 只检查到期的 RSS / Atom 信源；
2. 先用现有规则做相关性门控；
3. 对明确启用的 RSS 信源，访问无需登录的公开原文页并提取最多 4 段必要证据；
4. 每轮最多选择 3 条高相关候选调用已授权文本 AI；
5. AI 只输出结构化特征和证据判断，代码继续计算重要性、置信度和展示层级；
6. 通过自动门槛的结果直接进入信息流和当日简报，并标记“AI 自动发布 · 未经人工复核”；
7. 转向、证据不足、模型失败或分数处于中间区间的项目才进入管理员异常队列；
8. 简报按家庭和日期幂等更新，普通成员可以从 AI 情报首页直接看到最新结果。

“保存为知识”仍是成员主动操作，只进入知识中心归档资料；自动循环不会创建知识文档、待整理项目或
精选知识。

## 2. 正文与版权边界

- 默认信源继续只使用订阅标题和简介；管理员必须逐个把 RSS 信源设置为“提取公开网页证据摘录”。
- 只使用公开 HTTP/HTTPS 页面，不发送 Cookie，不登录，不执行脚本，不绕过反爬或付费墙。
- HTTP 401/402/403、登录/订阅提示和正文不足均安全降级为元数据模式。
- 不保存网页 HTML、完整正文、图片、评论、导航或广告；数据库只保存最多 4 段、合计不超过 5,000
  字符的必要证据摘录和不可逆内容指纹。
- 云端 AI 只在 Provider 明确采用 `public_article_snippets` / `public-article-snippets-v1` 后接收这些
  摘录；旧 `public_metadata_only` 授权仍可继续运行，但只发送标题和订阅简介。
- 家庭知识正文、成员备注、API Key、Cookie、付费全文和原文 URL 不进入 AI 输入。

## 3. 自动发布门槛

自动候选只来自 A、B、C 级信源，且规则初筛相关性不低于 45、重要性不低于 40。AI 完成后必须同时
满足：

- 相关性不低于 55；
- 重要性不低于 50；
- 置信度不低于 55；
- 实质性和证据清晰度均不低于 45；
- 有有效来源引用；
- 变化标签不是“转向”。

最终进入“今日精选”还是“全部动态”仍由 `people-v1` 代码评分决定。低于噪音门槛的结果自动移入
噪音箱，原始来源和分析审计不删除。中间区间、转向和失败项保持待复核。

## 4. 调用与费用上限

- 每轮最多 3 条新 AI 分析；
- 每个家庭每天最多 5 次 AI 分析尝试；
- 按 Provider 单次费用上限保守预留，每天最多 0.05 美元；
- 相同 Provider、模型、提示词版本和输入指纹复用已有成功分析；
- AI 失败不删除来源条目，管理命令返回非零状态供 DSM 记录失败。

## 5. 管理命令

为明确选择的 RSS 信源启用公开证据提取：

```text
python manage.py enable_intelligence_article_sources \
  --source-id <ID> [--source-id <ID> ...] \
  --confirm-public-html
```

把已有文本 Provider 从公开元数据授权升级为公开必要证据摘录授权：

```text
python manage.py enable_intelligence_article_ai \
  --provider-id <ID> \
  --confirm-public-article-snippets
```

运行一次完整循环：

```text
python manage.py run_intelligence_cycle \
  --family-id <家庭ID> \
  --provider-id <Provider ID> \
  --max-items 20
```

正式 NAS 任务建议每 60 分钟运行一次。任务只调用 Django 管理命令，不引入 Celery、Redis 或常驻
爬虫；首次真实运行、费用和页面验收通过后再创建 DSM 计划任务。

## 6. 页面职责

- AI 情报首页：优先展示最新简报和自动发布动态；GET 不联网、不调用 AI、不批量写入。
- 情报简报：日常只读；手工 AI 整理和重建简报收进“维护与故障恢复”。
- 运行状态：展示最近自动循环、信源正文策略、网页提取结果、任务审计和错误摘要。
- 候选复核：只处理异常与边界项目，不再承担每条日常新闻的发布确认。
- 事件详情：原始来源、公开证据摘录、AI 结果和自动发布状态分开显示。

## 7. 首轮生产验收

1. 部署前创建并验证 PostgreSQL 备份，记录源码回滚点和业务基线。
2. 只为 1–3 个已确认的官方或可信媒体 RSS 启用公开证据提取。
3. 显式升级现有 DeepSeek Provider 的数据范围，不读取或改写 API Key。
4. 手工运行一次完整循环，核对正文提取状态、AI 输入审计、Token、费用和自动分流。
5. 用管理员和普通成员分别检查首页、简报、事件详情和运行状态的桌面/手机布局。
6. 确认生产财务业务基线、`.env`、上传文件和数据库卷未被部署覆盖。
7. 通过后创建每 60 分钟 DSM 任务，并观察至少一次无新增内容的幂等运行。
