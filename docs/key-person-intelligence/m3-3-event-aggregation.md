# M3.3 跨来源事件聚合与人工复核

状态：Implemented locally

更新时间：2026-08-16

## 1. 目标与产品边界

M3.3 解决同一动态被官网、监管披露和财经媒体分别报道后重复占据信息流的问题。系统保留每条
`SourceItem` 和原始 `IntelligenceEvent`，只把确认属于同一事实的事件聚合为一张日常事件卡。

本段不启用 AI 自动合并：

- 采集流水线继续自动处理 URL、外部 ID、内容指纹和确定性事件键完全相同的重复项；
- 跨来源近似事件由 `event-merge-v1` 代码策略产生建议，不调用文本模型；
- AI 分析可以作为管理员阅读材料，但不能修改建议状态或执行聚合；
- 语义自动聚合固定关闭，至少积累真实误合并率和拆分记录后再单独评审。

## 2. 分级处理

候选必须属于同一家庭、共享关注主题、发生时间相差不超过 3 天且来自不同信源。策略依据标题与
摘要相似度、共同数字、事件类型和时间距离计算 0–100 分：

- 低于 48 分：不生成建议，不制造管理员待办；
- 48–74 分：进入“需要单项确认”；
- 75 分及以上：在没有保护状态时进入“高置信度批量建议”；
- 90 分及以上只记录“未来可评估自动处理”的资格，当前仍不会自动合并。

任一事件已经发布或人工复核、保存到知识中心、被成员收藏时，无论分数多高都只能单项确认。管理员
拒绝一对建议后，同一策略版本不会反复提示；策略升级需要新版本重新评估。

## 3. 主来源与证据

默认主来源按来源等级、来源类别、内容深度、是否保存摘录和载体权重排序，优先监管、官方、人物
直接来源和更完整的正文。管理员在单项确认页可以改选：

- 保留哪条事件作为标题、摘要和人工状态主体；
- 采用哪条已保存来源作为主来源。

其他来源不会丢弃，全部作为证据并入保留事件。若被并入事件已经保存到知识中心，服务端拒绝把它
作为副本隐藏，管理员必须改为保留该事件；两边均已归档时不允许聚合。

## 4. 可逆操作与审计

`EventMergeSuggestion` 保存策略版本、分数、分层、依据、推荐事件、推荐主来源和复核人；
`EventMergeRecord` 保存保留事件、并入事件、操作人、时间和拆分快照。

确认聚合时：

- 复制缺少的证据和主题关系到保留事件；
- 被并入事件只设置 `merged_into`，不删除事件、来源、AI 分析或成员状态；
- 信息流和普通成员详情只展示保留事件；管理员仍可查看原事件；
- 新证据组合会使保留事件当前 AI 分析失效，历史版本继续保留；
- 已读和收藏按成员取并集，避免聚合导致成员操作丢失。

拆分时只移除本次聚合复制的证据和主题，恢复原主来源与时间范围，并让原事件重新显示。为避免删除
成员在聚合后形成的阅读或收藏状态，已读与收藏并集不会自动回退；这是一项有意的保守策略。

## 5. 页面与权限

管理员导航新增“重复复核”：

- 高置信度建议支持最多 50 项勾选批量确认；
- 灰区或保护状态候选提供双栏来源对照、保留事件和主来源选择；
- 事件详情展示待处理建议、已并入原事件和“拆分恢复”；
- 所有写操作均为 POST 并执行家庭管理员、家庭归属和当前状态校验；GET 不刷新建议、不聚合事件。

普通成员和只读成员不能访问复核页面。访问已并入事件的旧链接时，普通成员跳转到保留事件。
