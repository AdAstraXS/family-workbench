# 全局 AI 原型结果：查询可行，建议质量与 Harness 兼容性未过关

日期：2026-09-05。分支：codex/global-ai-spike。范围：本地虚构数据实验，无生产接入或部署。

后续口径更新：用户确认全局 AI 默认按模块独立查询。2026-09-05 在后续分支将虚构工具拆为
账本快照与投资持仓两个入口，移除自动去重、对账和合并；23项测试通过，离线 Codex stdio
重新发现5个只读工具。以下21项、4工具和两轮真实API数字保留为原始实验记录，不回写历史结果。

## 决策建议

保留 Django 受控查询和模型无关的记忆设计。普通 API 工具调用已完成两轮连续问答；
Codex stdio 与 MCP 工具发现已通过，但 Codex 0.153.4 拒绝本轮 DeepSeek 的 chat 协议配置，
没有提交 Codex 模型请求。因此没有同模型 Harness 对照结果，不能比较两者回答质量或费用。

首版可优先建设带引用的事实查询；资产配置建议继续作为未通过质量验收的能力，不直接上线。
两轮样本不足以评价 DeepSeek 总体能力；只说明本次模型／提示／数据组合不能直接用于正式建议。
未为迁就 Harness 建立协议转换器，未改用其他人的订阅或账户。

[原型代码与运行说明](../experiments/global_ai/README.md)。Python 3.13.7，Codex CLI 0.153.4。
使用系统已安装的固定版本，没有升级或替换客户端。生成的协议 schema 用于核对参数。

21 项 unittest 通过，含实际 MCP 子进程以及本地超时／进程退出检查。
Codex initialize、thread/start、thread/read、mcpServerStatus/list 均完成，发现 family_fixture 的 4 个工具。
初次 MCP 未知方法错误未保留请求 ID，导致发现流程超时；现已修复并补回归断言，重跑通过。

| 场景 | 结果与含义 |
| --- | --- |
| 本人资产 | 100 万元：股票 50 万、债券 20 万、现金 30 万；全部虚构 |

上述 actor 是实验宿主指定的固定身份，没有实现 Django 网页登录；这些是隔离规则测试，不是网站验收。
取消测试覆盖状态拦截和本地子进程清理，不代表真实 Codex 推理取消或供应商停止计费已经通过。

## 真实 API 样本

使用已有 KNOWLEDGE_TEXT_AI_API_KEY，向 DeepSeek 官方端点发送虚构数据。
没有输出密钥，没有上传 .env、真实资料、账本或资产数据。使用 deepseek-v4-flash 非思考模式。

两轮各包含首问和连续追问；同一工具集合提供资产、记忆、知识搜索与精确正文。
每轮 4 次 API 请求、5 次工具调用；没有网络自动重试。

| 样本 | 耗时 | 输入 Token | 输出 Token | 总 Token | 人工质量结论 |
| --- | --- | --- | --- | --- | --- |
| v1 | 11.19 秒 | 4364 | 859 | 5223 | 不通过：无依据认定股票50%符合30%回撤要求 |
| v2（收紧证据要求） | 10.32 秒 | 4973 | 1050 | 6023 | 不通过：追问中无依据断言纯投资收益达不到12% |

共 8 次 API 请求、11246 Token。输入含供应商报告的缓存 Token；耗时为单机单次实验，不是性能基准。
没有核对供应商账单，未把旧单价换算成所谓实际费用。

两轮正确读取了虚构资产金额与占比，均使用相关资料，结果中未出现 Bob 私密标记。
这不能证明所有提示下均不会泄露。v2 修正了首轮回撤断言，但引入了新的无依据收益判断，
并出现把提示规则复述给用户、文字冗余以及将去重记录说成“混入”的问题。

因此“成功完成调用”与“可向用户提供建议”必须是两个状态。
不能只用引用存在、免责声明存在或词语黑名单作为财务建议质量门槛。
下一阶段评测应同时覆盖无依据的乐观与悲观判断、出入金与收益混淆、跨模块误合并、连续追问漂移。

本地原始证据（不提交）：outputs/global-ai-spike/live-result.json 为 v1；
synthetic-v2-result.json 为 v2；offline-result.json 为最终无模型协议检查。

## Codex 实测兼容性

采用隔离 CODEX_HOME，未使用现有 ChatGPT 订阅凭据。自定义 provider 设置同一 DeepSeek 模型和
chat 接口，在 thread/start 阶段收到明确配置错误：wire_api="chat" 已不再支持，要求 responses。
这与先前在线配置文档曾提及 Chat Completions 的信息存在版本差异，安装二进制实测决定本轮结果。

本次没有核验 DeepSeek 是否另有可用的 Responses 端点，也没有因此断言所有 DeepSeek／本地模型
永远不能接 Codex。需要更换兼容接口或供应商才能继续 Harness 质量对照，但本轮不扩大范围。
直接使用普通 API 访问同一服务商成功，不需要通过 Codex 才能实现受控查询。

## 尚未通过与下一阶段边界

- 实际 NAS 架构、资源开销及多人并发未验证。
- 未实现网站页面、Django session 身份传递、流式响应、持久模型会话恢复。
- 账本和投资模块的真实只读服务、外币缺失、历史行情和回撤计算未验证；原型仍是 CNY 虚构样本。
- 记忆编辑版本、共享记忆、云端授权、历史答案撤权与向量索引生命周期尚未实现。
- 未做模型级提示注入、复杂长文检索、不同模型切换或大样本评测。
- 没有通过 Codex 的真实模型回合，因此不宣称 Harness 多步分析、费用或取消验收完成。

后续建议先形成正式功能设计：复用已有资产事实与知识版本，提供个人／家庭范围的只读查询，
另建小型评测集筛选能稳定遵守证据边界的模型，再决定资产配置建议何时开放。
原型的“12%含投入增长目标”是虚构样本假设，不代表用户已确认该口径；用户实际提出长期复合年化12%、
不排除新增投入，其收益口径仍待确认。30%为回撤承受要求，不修改现有投资目标计算或生产数据。
