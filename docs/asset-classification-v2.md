# 全站两级资产分类

投资组合、家庭账本、首页和 AI 只读账本工具共用 `AssetCategory` 字典。记录保存二级
类别，通过 `parent` 取得一级类别，页面分别选择一级和二级，不重复保存两组可能矛盾的值。
股票、ETF、债券、期权、基金、其他仍为独立金融品种，继续参与交易和估值。

## 已确认字典与映射

| 一级 | 二级 |
| --- | --- |
| 现金及现金等价物 | 现金、货币基金 |
| 固定收益类 | 短期国债、中长期国债、债券基金 |
| 权益类 | 股指基金、股票基金、股票 |
| 衍生品 | 期权 |
| 另类投资 | 虚拟货币 |
| 商品类 | 黄金 |
| 保险类 | 储蓄型保险 |
| 负债 | 信用卡 |

国债按原始发行期限划分，≤1年为短期，>1年为中长期；发行日或到期日不足时不以剩余
期限推测。国债 ETF 为中长期国债；黄金和虚拟货币 ETF 跟随其对应资产。宽基指数及其
杠杆基金归股指基金，XLU、XLV 等行业 ETF 归股票基金。多资产基金依据股债主次归类，
未核实的标的不凭 ETF 金融品种推测。

支付宝旧基金余额归股票基金；银行、医保的旧固定收益余额归现金；养老金余额归储蓄型
保险；可识别的套利余额归现金。券商账户的旧一级合计可能包含股票与基金，或现金与债券，
无法一一对应时保留原分类并列为待确认，不拆分金额或猜测产品构成。信用卡正余额先核对
溢缴款，不改变金额符号。

## 结构安装与历史调整分开

`family_core.0009`、`portfolio.0032` 增加父类别、调整审计、债券原始发行日和快照明细
分类。`family_core.0010` 只安装字典，保留旧一级类别和所有财务记录；遇到字典名称冲突
停止迁移，不自动重用或改挂历史类别。

新投资快照明细保存当时分类，历史展示不跟随证券现有分类变化。旧快照新增字段为空，
显示“历史分类待确认”，不会因访问页面隐式抓行情、刷新快照或填充分类。旧账本导入格式
继续兼容；新格式支持二级名称或“一级 → 二级”完整路径。旧合并类别需先预览。

家庭账本快照列表增加“资产分类与历史映射”入口。登录成员只能生成所属家庭的只读预览，
选择日期后点击“生成映射预览”。日期限制交易、账本及快照明细；证券主数据不分日期。
已确认的二级类别保留；跨家庭共享证券不能被本家庭类别覆盖。

预览命令默认只读：

```text
python manage.py preview_asset_classification --family FAMILY_ID --start YYYY-MM-DD --end YYYY-MM-DD
```

历史写入必须先核对实际生产预览、确认日期范围及待确认项目，创建并验证生产备份，然后
使用同一日期范围和预览的 `digest` 显式执行 `--apply --expected-digest DIGEST`。生产
执行仍必须遵循 NAS 技能及受限包装器，不得以本地库覆盖 NAS，不得绕过包装器白名单。
页面没有写入按钮；此命令不会自行创建生产备份。

应用时锁定本家庭及目标记录、重新验证预览摘要，只更新已确定记录的类别外键，每条留存
旧分类、目标分类和批次。执行后比较所有非分类存储字段的摘要，任何变动导致整批回滚。
数量、金额、价格、汇率、成本、收益、快照完整性等不重算；未知记录保留，重复调整幂等。

## 本轮验收与边界

- 使用独立本地 PostgreSQL 测试库，不迁移本地业务库或生产库。
- 投资组合、IPO、账本、首页、家庭核心及 AI 工具共 495 项回归通过，包含 25 项分类专项；
  模型迁移一致性、Django 检查和 JavaScript 语法检查通过。系统检查只保留本地旧环境的
  OneNote 未配置、令牌密钥未配置及 Readability 未安装三项已知提示，本轮没有新增依赖。
- 校验层级/家庭/金融品种、原始期限、历史保全、过期预览拒绝、幂等、审计和只读页面。
- 页面服务器渲染与双选择器测试通过。浏览器工具因本机沙箱启动错误不可用，交互和手机视觉
  验收仍待补做，不能以服务器渲染测试替代。
- 本轮未部署、未写生产数据。实际生产全量映射、日期范围确认和经验证备份仍为发布前条件。
- 本机离线预览使用 2026-10-03 保存的 2026-03-31 账本明细。证据缺少账户类型及产品构成，
  不能把其中待确认数量视为当前 NAS 的全量结果；敏感预览不进入 Git。
