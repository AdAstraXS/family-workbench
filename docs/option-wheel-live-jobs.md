# 实时分析任务与结果回显

## 页面流程

管理员仍从 `/option-wheel/` 选择已就绪账户和启用标的，确认“仅分析、不下单”。
POST 只创建持久化任务并启动独立进程，立即返回任务编号；不再让浏览器连接承载整段行情查询。
页面每 3 秒以只读 GET 查询任务，完成后显示分析链接。刷新或离开页面后，从“最近分析任务”
进入任务详情即可继续查询。未启用 JavaScript 时，提交后跳到任务页，手动 GET 刷新即可。

任务明确区分等待启动、分析与清理中、已保存、未保存及中断。提交响应丢失时只按原任务编号
查询，不自动重发 POST。连接异常不代表后台失败，达到页面轮询上限也不代表取消任务。
这是运行状态，不显示虚构进度百分比。仍只采集代表合约，不是最优合约扫描，不含外接 AI。

## 并发、权限和保存

- 提交凭证签名绑定家庭和请求 UUID，有效期两小时；同一凭证幂等。
- 同一家庭最多一个等待/运行任务，由家庭行锁和数据库部分唯一约束共同保证。
  多标签页提交不同选择时返回当前活动任务，并显示实际账户与标的，不偷偷追加范围。
- 状态和详情仅当前家庭可读；只有管理员可提交。GET 不抓行情、不启动进程、不修复数据库。
- 工作进程采用条件更新领取任务，同一任务不会被两个进程重复处理。
- 查询前后重新核验账户和策略；保存前重新检查管理员有效性、任务状态和保存期限。
- 全部账户/标的分析及任务成功状态在同一事务中提交，任一失败整批回滚。
  同一任务跨账户复用完全相同的期权报价证据；字段不一致拒绝保存，旧证据不修改。
- 交易连接和执行闸门保持关闭；全额现金担保、实股覆盖、行情、事件及其他金融门控不放宽。

## 进程与中断

`run_wheel_analysis_job <UUID>` 仅处理已有授权任务；网页按需启动它，不是定时采集任务，
不需要新增 DSM 调度、Celery、Redis 或独立服务。它再启动无数据库写入的行情子进程，
沿用 `m1-gate` 及原有跨进程行情锁；正常结束须核对临时订阅恢复。

行情子进程总上限 180 秒，整个任务保存期限 240 秒。查询超时会结束子进程并明确提示未保存、
订阅清理需核对；不把进程被结束等同于已验证清理。网页只接受固定协议和白名单诊断，
不显示 SDK 原始错误或凭证。

独立工作进程可越过 HTTP 请求结束，但不跨容器重启。容器重启或工作进程异常退出后，
到保存期限时 GET 显示“超时或中断，需核对”；不会自动重新执行。下次明确提交时，在锁内
将过期任务结束后才能创建新任务。迟到的旧工作进程没有保存资格，事务内再次检查期限。
管理命令未完成保存返回非零状态；详细安全提示保留在网页任务记录。

## 部署与验收边界

迁移 `0008_wheelanalysisjob` 只新增任务状态表及唯一约束，不重写历史财务数据。
依赖和 Compose 均未变化。NAS 部署前仍须验证数据库备份，再按精确提交更新代码、迁移及静态资源。
本地测试/模拟浏览器样本不能替代 NAS 上独立进程启动及真实盘中任务的最终验收。

页面将排除原因译成中文；“新鲜”明确为采集时冻结状态。行权模型概率不等于真实提前指派概率，
历史权利金不承诺当前成交。收盘观察模块在本轮保持原行为，收盘链查询问题继续暂停。
