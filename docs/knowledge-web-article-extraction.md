# 网页收藏正文提取

## 范围与流程

成员主动粘贴公开网页链接后，Firecrawl 获取 HTML，Mozilla Readability 0.6.0 在本地后台任务中
识别正文。jsdom 30.1.2 只创建不执行脚本、不加载外部资源的 DOM；不使用浏览器 Cookie，也不
把正文发送给额外 AI 清理服务。继续沿用成员原有的 AI 整理授权。

新收藏处理顺序：获取网页 → 本地提取并验证正文 → 归档原始响应及提取结果 → 仅下载正文图片
→ 按原授权生成 AI 建议。展示、搜索、图片下载和 AI 都使用同一份固化后的正文，不分别重算。
正文提取仍需后续 HTML 安全净化及原有 SSRF、资源类型、附件权限和大小限制。

通用规则适用于常见新闻、中文长文、英文博客、普通 div 排版文章；富途和微信公众号提供正文
容器增强，规则不匹配时仍运行通用提取。保留正文链接、表格、普通插图、静态图表与图注，支持
data-src、data-original、data-lazy-src 和 srcset 延迟加载。不按“图片小/没有图注”一刀切删除。
已识别的广告、评论、推荐、分享、导航、隐藏元素、1×1 像素及富途 boundary-pic 不归档为正文。

低于 120 字符、链接文字占比过高、疑似登录/付费提示且正文不足的结果拒绝归档，并在原收藏记录
显示“正文识别待确认”；没有整页兜底，也不对失败结果下载图片或调用 AI。此检测不保证识别全部
截断页面。论坛、多篇混排、图集、登录后或付费内容需要成员核对或使用允许保存的正文文件导入。

## 版本与既有资料

不改数据库结构。新快照 JSON 保留 html/rawHtml/markdown/metadata，同时追加 article 字段，记录
提取 HTML、引擎版本、方法、文字长度和图片数；原获取内容不覆盖。任务 result 记录提取摘要，
网页显示正文图片数量。原件仍通过鉴权下载，不能作为不可信 HTML 直接渲染。

旧快照没有 article 时继续按旧 HTML 渲染，不在 GET、补图片、重试 AI 时自动提取或重抓。成员
主动选择“重新抓取，保留旧版本”后才应用新提取规则，成功产生新的不可变版本；提取失败时旧
正文、附件和人工确认结果仍保留。人工确认结果不被新抓取覆盖，旧 AI 建议按现有版本机制处理。

## 运行与发布

app/Dockerfile 使用 Node 22.23.2 的构建阶段安装 package-lock.json 固定依赖，运行镜像只复制
Node 与 /opt/article-extractor/node_modules；不安装 npm 到运行镜像，不新增常驻服务或端口。
依赖路径与源码挂载分离，排除开发 node_modules。构建时 npm ci --ignore-scripts，禁止安装脚本。

Django 以固定脚本、JSON 标准输入和无 shell 子进程调用，清除继承的数据库/AI 密钥及 NODE_OPTIONS；
输入上限 20 MiB、JS 堆 256 MiB、最多 30000 个 DOM 元素、运行上限 15 秒。KNOWLEDGE_READABILITY_NODE
仅用于指定本地 Node 可执行文件，默认 node。管理命令系统检查 knowledge.W003 检查解释器及模块，
未就绪时旧资料可读，新收藏不能可靠处理；不回退整页。

发布必须遵循 NAS 部署技能，先备份并校验数据库，基于精确 Git commit 安装 app/，成功 build-web
后才 restart-web。不能只挂载新源码并复用缺少 Node 的旧镜像。部署前后核对实际生产 commit，
与其他部署对话协调串行发布；合并最新生产改动并复测，保留数据库、上传资料、配置和 OpenD 状态。
