# 宏观数据自动维护

## 页面和数据行为

- 官方目录：人民银行金融统计目录、商务部日常新闻发布、统计局最新发布。目录分页有上限、站点有白名单，正文的统计期和发布日期必须核验后才入库。
- 支持央行合并报告及早期金融/社融存量/累计增量分开发布。不把当月增量当作年初累计，不把未披露字段补为零。
- 基建旧报告的“不含电力、热力、燃气及水生产和供应业”口径使用独立指标代码，避免和当前包含这些行业的口径拼接。
- 来源页的“更新记录”显示真实后台任务状态、检查是否超过预期间隔、失败报告和发布日期覆盖。GET 只读取数据库。
- 正式定时运行与手工验证分别验收；一次成功不能证明定时任务已启用。
- 失败返回非零状态，并保留以前数据。PostgreSQL 会话锁防止并行维护；进程中断后锁自动释放，下一次写入任务保留中断记录并重新检查。

## 命令

默认只读，不创建采集、报告或日历数据库记录：

```text
python manage.py update_macro --mode official
python manage.py update_macro --mode structured
python manage.py update_macro --mode calendar
```

正式更新必须显式加 `--write`。官方任务默认检查当前月及之前两个月，并发现ISM当前制造业、服务业报告和核验BLS就业/CPI/PPI发布稿。结构化模式刷新全部已登记接口。指定历史范围或采集组的官方回补不额外读取ISM与BLS，不扩大已确认范围。

历史试算先指定统计期和目录分页上限，再确认生产范围并备份：

```text
python manage.py update_macro --mode official --start 2025-01-01 --end 2026-08-01 --pages 45
```

重复写入同一数据保持幂等；数值或实际发布日期发生变化时增加修订，保留来源地址、响应校验值和字段证据。

## 正式 NAS 定时任务

在 DSM 任务计划创建三个独立任务：

| DSM ID / 名称 | 北京时间 | 模式 | 日志 |
| --- | --- | --- | --- |
| 16 / family-workbench-macro-official | 每天 11:20、18:20 | official | logs/macro-official.log |
| 17 / family-workbench-macro-structured | 每天 06:40 | structured | logs/macro-structured.log |
| 18 / family-workbench-macro-calendar | 每天 07:40 | calendar | logs/macro-calendar.log |

任务使用已批准的 Container Manager 和 Django 命令，不引入独立任务系统。每次写入前先用既有部署包装器创建并验证带时间戳的数据库备份，失败立即停止。随后运行 `docker compose exec -T web python manage.py update_macro --mode <模式> --write`，日志追加；保留命令非零状态供 DSM 错误记录。核对任务 ID、owner、enabled、下次运行时间、执行日志和网页状态。备份不自动清理，沿用项目保护约定。

2026-10-05 已确认三个任务均为 root、enabled，DSM 下次时间与实际调度登记一致。三个脚本共用 `logs/macro-maintenance.lock`，避免备份和维护阶段交错。接口任务的首次历史回补限定 2025-01 至 2026-08，成功后写入 `logs/macro-backfill-202501-202608.done`，以后跳过首次回补。

## 发布日历

核验统计局年度日历、BEA 和 BLS 官方 ICS、Census 和 ISM 官方日历表。数据库保存多个已核验版本，页面按来源采用最后核验版本；失败保留上一版及告警。新增年份只随官方来源出现，不从去年机械复制。

美国发布时间用 America/New_York 转换到北京时间，包含夏令时。计划只作为计划，不能补填实际观测发布日期。官方报告的实际日期随导入记录进入日历；FRED CSV 不提供实际发布日期，仍保留为空。
