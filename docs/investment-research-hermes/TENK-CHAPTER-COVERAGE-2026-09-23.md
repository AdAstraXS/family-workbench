# 通用 10-K 章节与区段覆盖（2026-09-23）

此前投研 AI 只能按每段 16,000 字选择正文。成员不知道 Item 1、1A、7、8 等章节落在哪些区段，也容易将“有区段草稿”误认为整章已核查。本次在已保存的不可变正文版本上建立**只读章节索引**：资料页列出标准 Item 标题，显示涉及区段中有多少区段已生成当前成员的成功草稿，点击标题可按原版本、字符位置和 SHA-256 高亮原文。档案页的区段选择项也显示涉及的 Item。未识别标题明确标“未识别到独立标题”，不猜测位置或完成状态。

章节边界取识别到的下一标准 Item 标题；目录簇和不符合标准标题的句子会被排除。区段可能跨两个章节，覆盖数字按机械交集计算，**只表示模型读过相关区段，不代表逐句审阅、完整核查或章节结论可靠**。GET 页面不发 SEC 或模型请求，不写数据库；原正文、引用坐标、草稿数据和权限均未改变。

## 开源项目取舍

- [EdgarTools](https://github.com/dgunning/edgartools)（MIT）已提供 10-K Item 提取和 XBRL 能力，适合未来需要独立解析多公司原始 HTML 与结构化财务数据时评估；它有自己的解析文本和依赖体系，直接替换当前正文会破坏现有不可变版本的字符引用，也会改变 NAS 镜像构建范围。
- [sec-parser](https://github.com/alphanome-ai/sec-parser)（MIT）将 SEC HTML 解析为语义树，适合复杂排版的后续试验；当前产品需要的是**已保存正文的精确坐标与草稿覆盖**，仍需编写映射与校验层。
- 因此这一步只增加标准 Item 标题的保守索引，不重新开发 SEC 下载器、HTML 解析器或财务事实提取器，也未新增依赖。若后续遇到大量无法定位或误定位的文件，再用上述库与现有引用坐标进行对照试验，验证成功后再决定接入。
